# v2 법령 검색 변형의 오프라인 비교(개발용)

> 처음 읽는다면: [전체 흐름 안내](overview.md) · [용어집](glossary.md)

- 날짜: 2026-10-19
- 목적: v2 엔드투엔드 실패 분석([v2-e2e-failures.md](v2-e2e-failures.md))에서 가장 많았던 등급 2(정답 법령 구간이 검색 상위 8개 밖)를 검색 범위나 검색어로 줄일 수 있는지 유료 호출 없이 먼저 본다.
- 범위: 개발용 v2 시나리오 로그만 썼다. 미공개 시나리오 로그와 원문은 쓰지 않았다. 엔진 코드, 고정 설정, 평가 문서, 결과 수치는 바꾸지 않았다. 판정이나 주장이 아니라 다음 결정을 위한 개발용 확인이다.

## 방법

- **자료:** `dev-v2-r0-1~3`, `dev-v2-r4-1~3`(개발용 시나리오 12개 × 3회, 정답 법령 항목 15개). 근거를 고른 검색 이벤트는 R0 399개, R4 397개다.
- **측정 시점:** 깔끔하게 다듬은 질문 모음이 아니다. 개발용 상담에서 엔진이 실제로 법령 검색을 한 시점(근거를 고른 `retrieval.done` 이벤트)마다, 그 시점까지 실제로 오간 대화로 검색어를 만들어 검색을 다시 돌렸다. 고객이 아직 단서를 말하지 않은 초반 턴도 그대로 들어간다.
- **검색:** 로그의 대화로 고정 커밋의 법령 검색(R0 BM25 규칙 검색, R4 로컬 임베딩 + BM25 결합)을 이 PC에서 다시 돌렸다. 고정 규칙으로 돈 `-3` 실행에서 다시 만든 검색어와 상위 8개가 기록과 모두 같았다(R0 137/137, R4 134/134).
- **지표:** 근거 이벤트 × 정답 법령 항목마다, 상위 k개 구간이 그 항목을 덮는지(`docs/evaluation.md` §4.2 기준, 대체 근거 포함). 고정 전 검색어 규칙 비교(`jikgam/v2/e2e_queries.py`, ADR 0027)와 같은 정의다.
- **변형:** 문서 형식이나 법령 번호 체계를 보는 규칙 없이, 설정 값과 일반 규칙으로만 만들었다(`jikgam/v2/law_variants.py`).
  - (a) 지금 그대로: 고정 규칙의 검색어(전체 고객 발화 + 의도·표현 확장).
  - (b) 적용 문서로 제한: 검색 결과에서 조직 A에 적용되는 문서 밖의 구간을 빼고 상위 k개를 채운다. 문서는 구간 메타데이터에서 읽는다.
    - 적용 문서 목록은 조직 설정 값처럼 실행 인자로 넘겼고, 결과를 보기 전에 정했다.
    - 조직 A(온라인으로 파는 구독형 디지털 콘텐츠)에 적용되지 않는 온라인게임 표준약관 하나만 뺐다. 나머지 9개 문서(전자상거래법·시행령·시행규칙, 약관규제법, 소비자기본법, 콘텐츠산업 진흥법, 소비자분쟁해결기준, 콘텐츠이용자 보호지침, 전자상거래 표준약관)는 남겼다.
    - 개발용 정답 15개 중 뺀 문서에만 있는 것은 없다.
  - (c) 판별 결과로 만든 검색어: 고객 발화 대신 그 시점까지의 판별 결과만 쓴다. 요청은 직전 근거 판단의 의도를 조직 설정의 의도 낱말(`intent_terms`)로, 확인된 사실은 업무 응답의 범주·제목 값(이름 같은 식별자, 수치 제외)으로 바꾼다.
    - 세션의 첫 검색처럼 판별 결과가 아직 없으면 (a)를 쓴다(R0·R4 각 36개 이벤트).
  - (d) (b)와 (c)를 함께.

## 결과

| 변형 | R0 상위 8개 | R0 16위 안 | R4 상위 8개 | R4 16위 안 |
|---|---|---|---|---|
| (a) 지금 그대로 | 38.9% (197/506) | 50.0% (253/506) | 45.2% (228/504) | 51.6% (260/504) |
| (b) 적용 문서로 제한 | 43.3% (219/506) | 53.0% (268/506) | 46.6% (235/504) | 53.4% (269/504) |
| (c) 판별 결과로 만든 검색어 | 25.3% (128/506) | 29.1% (147/506) | 31.5% (159/504) | 33.9% (171/504) |
| (d) (b) + (c) | 27.3% (138/506) | 37.7% (191/506) | 31.5% (159/504) | 33.9% (171/504) |
| (e1) 최근 고객 발화 1개 | 20.8% (105/506) | 33.4% (169/506) | 34.7% (175/504) | 40.3% (203/504) |
| (e2) 최근 고객 발화 2개 | 23.9% (121/506) | 35.0% (177/506) | 37.9% (191/504) | 48.2% (243/504) |
| (f) LLM 재작성 | 20.9% (106/506) | 36.6% (185/506) | 30.4% (153/504) | 45.6% (230/504) |
| (g) (b) + (f) | 23.3% (118/506) | 38.1% (193/506) | 31.9% (161/504) | 50.4% (254/504) |

괄호 안은 덮은 항목 수 / 근거 이벤트 × 정답 항목 수다. 아래의 %p 차이는 반올림 전 값으로 셌다.

(e1)~(g)는 뒤이어 같은 자료·같은 방식으로 잰 검색어 재작성 비교의 행이다. 합격선(R4 상위 8개 +15%p 이상)과 (f)의 지시, 재작성 지연·비용은 [v2-law-query-rewrite.md](v2-law-query-rewrite.md)에 실행 전에 적었다. 합격선을 넘은 변형은 없다.

- **세션 단위:** 세션의 검색들 중 한 번이라도 상위 k개에 든 구간으로 덮은 정답 항목은 다음과 같다(분모 45).
  - 상위 8개: R0 a 20, b 22, c 18, d 21 / R4 a 24, b 24, c 18, d 18
  - 16위 안: R0 a 26, b 31, c 21, d 27 / R4 a 25, b 27, c 21, d 21
- **보조:** (c)에서 확인된 사실 낱말을 빼고 요청 낱말만 쓴 경우는 상위 8개 R0 25.3%, R4 31.5%이고, 16위 안은 R0 30.8%, R4 35.7%다.

## 해석

- **(b) 적용 문서 제한은 두 프로필 모두 조금 올렸다.** 상위 8개 기준 R0 +4.3%p, R4 +1.4%p, 16위 안 R0 +3.0%p, R4 +1.8%p다. 다른 업종의 표준약관 구간이 상위 자리를 차지하던 몫이 정답 쪽으로 돌아온 것이다. 그래도 상위 8개가 덮지 못하는 항목이 R0 57%, R4 53%로 남아, 등급 2를 크게 줄이지는 못한다.
- **(c) 판별 결과 검색어는 두 프로필 모두 크게 낮췄다.** 상위 8개 기준 R0 -13.6%p, R4 -13.7%p다. 요청 낱말("해지 환불 결제" 등)은 의도마다 같은 몇 단어라, 고객 발화에 있던 구체적인 단서(언제, 무엇을, 왜)가 빠지는 것으로 보인다. 확인된 사실 값은 대부분 영어 코드(`active`, `card` 등)라 한국어 법령 글과 맞지 않았고, 상위 8개 결과는 요청 낱말만 쓴 경우와 같았다.
- **(d)는 (c)의 하락을 그대로 안는다.** (b)를 더해도 (a)보다 낮다.
- 이 자료에서는 (b)만 (a)보다 나았다. 엔진 반영이나 유료 재측정은 하지 않았다.

## 재현

```sh
uv run --group embed python -m jikgam.v2.law_variants results/engine/scenarios/dev-v2-r0-{1,2,3} results/engine/scenarios/dev-v2-r4-{1,2,3}     --documents ecom-act,ecom-decree,ecom-rule,terms-act,consumer-act,content-act,dispute-std,content-guide,ecom-terms
```

- 수치: `results/v2/law-variants/dev-v2/report.json`
- 이벤트별 검색어와 덮음 기록: `data/v2/local/law-variants/dev-v2/trace.jsonl`(저장소 밖)

관련: [v2-e2e-failures.md](v2-e2e-failures.md), ADR 0027(고정 전 검색어 규칙 비교), `config/v2/law.toml`
