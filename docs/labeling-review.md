# 판별 데이터 라벨 검토 기록

## 1차 데이터 (2026-10-12)

### 과정

1. 실패 유형별로 나눈 네 명의 작성자가 사례 105건(대화 그룹 40개)을 작성했다. 작성자는 모두 AI 에이전트다.
2. 작성자들이 보고한 규칙의 빈틈을 반영해 약관 문구(r2)와 라벨 기준을 먼저 고쳤다.
3. 작성자의 정답을 보지 않은 독립 검토자 세 명(AI 에이전트)이 같은 사례에 처음부터 라벨을 붙였다.
4. 작성자와 검토자의 라벨이 다른 항목을 하나씩 판정하고, 판정 기준을 라벨 기준 문서에 반영했다.
5. 판정 후 대화 그룹 단위로 분할을 배정하고 고정했다.

사람 검토는 아직 하지 않았다. 따라서 이 데이터의 정답은 "규칙 문서를 기준으로 AI 작성자와 AI 검토자가 일치하거나, 불일치를 판정한 결과"이며, 상담 실무자가 확인한 정답은 아니다.

### 사례 수정

- 첫 발화 시점(`known_facts`가 빈 상태)에 `condition_changed`를 묻던 5건에서 그 질문을 뺐다. 이제 검증 스크립트가 이를 막는다.
- g011-1: 마지막 발화의 내용이 `known_facts`에 미리 들어가 있던 것을 고쳤다.
- g021-2: 이전 시점의 발화를 가리키는데 그 발화가 대화에서 빠져 있던 것을 복원했다.

### 약관 문구 명확화 (r2)

판정에 영향을 주던 모호한 문구를 고쳤다. 금액과 결론이 바뀐 기존 사례는 없다.

- 7일 이내 계산법(결제일 다음 날이 1일째)
- 연 구독 이용 개월 수의 나머지 기간 처리와 10원 미만 절사 대상
- 월 구독 해지, 무료 체험 해지, 청약철회, 장애 환불 후 이용 마지막 날
- 중복 결제 중 어느 건이 중복인지
- 미성년자 판단 시점(결제 당시)
- 이용 정지 계정에서 제외되는 환불과 유지되는 환불
- 요금제 변경 시 일할 계산과 프로모션 적용 여부
- 제3자 문의에 대한 안내 범위

### 남은 한계

- test는 20건(대화 7개)이다. 결과를 비교할 때 차이가 몇 건인지 함께 보고해야 한다.
- `partial_stt`(미확정 자막) 사례는 3건뿐이고 test에는 없다.
- `next_info`는 `identity`에 치우쳐 있고, `payment_date`와 `usage` 사례가 거의 없다.
- 상담 실무자 검토를 거치지 않았다.

## test 사용자 검토 (2026-10-14)

`docs/evaluation.md` §8에 따라 사용자(프로젝트 결정권자)가 test 20건의 대화, 정답, 이유를 검토 화면(`scripts/make_test_review.py`)에서 직접 검토했다. 원본은 `data/reviews/test_review_2026-10-14.json`이다.

- 동의 14건: 출처를 `reviewed`로 바꿨다(빌드 파일에는 출처가 들어가지 않으므로 test 파일 해시 `5251d7d814279bf4`는 그대로다).
- 수정 필요 6건. test는 고정이므로 정답을 고치지 않았다.

| 사례 | 지적한 질문 | 요지 |
|---|---|---|
| g017-2, g026-1, g026-2 | sufficient, action | 정상 월 요금(별표 1)이 후보 조항에도 기록된 사실에도 없는데 처리 결과를 확정할 수 있다(true)고 봤다. 시스템 상수가 항상 주어진다고 볼지 입력 계약에 정해야 한다 |
| g017-2, g018-2 | sufficient | 처리 방법도 sufficient의 범위인데 환불 방법 조항(제14조)이 후보에 없다 |
| g018-2 | condition_changed | 기록된 요청에 새 요청을 더한 경우(범위 확장)를 조건 변경으로 볼지 기준이 모호하다 |
| g030-1 | intent | 부가 상품 해지와 환불 요구가 함께 있어 라벨 하나로는 의도를 다 담지 못한다. 처리 대상·해지·환불 요구를 나눈 구조를 제안 |
| g029-3 | (라벨 동의) | 고객이 진술한 계좌 명의를 확인된 것처럼 쓴 해설을 보완해야 한다 |

- 정답 변경을 요구한 판단은 위 다섯 사례의 10개다(g029-3은 라벨 유지). test 결과에는 이 10개를 뺀 결과를 보조로 함께 보고한다(`docs/evaluation.md` §8 보완).
- 지적의 공통점은 라벨 기준(`docs/data-format.md`)과 모델 입력 사이의 계약이다. 시스템 상수(요금표)와 절차 조항이 상태에 늘 있다고 볼지, sufficient의 "처리 방법"이 어떤 조항을 요구하는지, 요청 범위 확장의 condition_changed 기준이 정해져 있지 않다. 이 기준을 고치면 train·val 라벨도 다시 봐야 하므로, test 평가를 마친 뒤 라벨 기준 개정 과제로 둔다.
