# 판별 데이터 라벨 검토 기록

## 1차 데이터 (2026-10-12)

### 과정

1. 실패 유형별로 나눈 네 명의 작성자가 사례 105건(대화 그룹 40개)을 작성했다. 작성자는 모두 AI 에이전트다.
2. 작성자들이 보고한 규칙의 빈틈을 반영해 약관 문구(r2)와 라벨 기준을 먼저 고쳤다.
3. 작성자의 정답을 보지 않은 독립 검토자 세 명(AI 에이전트)이 같은 사례에 처음부터 라벨을 붙였다.
4. 작성자와 검토자의 라벨이 다른 항목을 하나씩 판정하고, 판정 기준을 라벨 기준 문서에 반영했다.
5. 판정 후 대화 그룹 단위로 분할을 배정하고 고정했다.

사람 검토는 아직 하지 않았다. 따라서 이 데이터의 정답은 "규칙 문서를 기준으로 AI 작성자와 AI 검토자가 일치하거나, 불일치를 판정한 결과"이며, 상담 실무자가 확인한 정답은 아니다.

### 일치율 (판정 전, 작성자 대 독립 검토자)

| 질문 | 일치 |
|---|---|
| applies | 338/340 |
| condition_changed | 93/96 |
| intent | 81/86 |
| sufficient | 82/85 |
| next_info | 45/47 |
| action | 86/88 |
| suggestion_valid | 22/22 |
| 전체 | 747/764 (97.8%) |

두 쪽 모두 같은 계열의 AI이고 같은 규칙 문서를 읽었으므로, 이 일치율은 규칙이 일관되게 적용되는지를 보여줄 뿐 정답이 맞다는 증거는 아니다.

### 불일치 판정

| 사례 | 질문 | 작성자 | 검토자 | 판정 | 이유 |
|---|---|---|---|---|---|
| g006-2, g021-3 | intent | other | compensation | compensation | 장애 보상(이용 기간 연장)을 위한 선택지를 새로 추가 |
| g016-1~3 | intent | cancel_refund | refund | refund | 청약철회 요청은 해지를 따로 말하지 않으면 refund로 통일 |
| g020-3 | applies:A-04 | true | false | false | 같은 결과를 주는 조항이 둘이면 직접 규정하는 조항(A-07)만 필요 |
| g040-1 | condition_changed 외 3개 | 결제일을 물음 | 기록 기준 안내 | 검토자 쪽 | 결제 내역이 이미 조회돼 있으면 기록이 기준(g026-2, g027-2와 같은 기준) |
| g012-3, g029-2 | condition_changed | false | true | false | 처리 방침에 맞지 않는 구체적 값을 처음 제시한 것은 새 사실 |
| g026-2, g027-2 | sufficient 외 | 기록 기준 안내 | 다시 물음 | 작성자 쪽 | 조회된 기록이 기준 |
| g033-2 | sufficient | false | true | false | 법정대리인 동의 여부는 고객 진술뿐이고 시스템으로 확인되지 않음 |

### 사례 수정

- 첫 발화 시점(`known_facts`가 빈 상태)에 `condition_changed`를 묻던 5건에서 그 질문을 뺐다. 이제 검증 스크립트가 이를 막는다.
- g011-1: 마지막 발화의 내용이 `known_facts`에 미리 들어가 있던 것을 고쳤다.
- g021-2: 이전 시점의 발화를 가리키는데 그 발화가 대화에서 빠져 있던 것을 복원했다.

### 약관 문구 명확화 (r2)

판정에 영향을 주던 모호한 문구를 고쳤다. 금액과 결론이 바뀐 기존 사례는 없다.

- 7일 이내 계산법(결제일 다음 날이 1일째)
- 연 구독 이용 개월 수의 나머지 기간 처리와 10원 미만 절사 대상
- 월 구독 해지, 무료 체험 해지, 청약철회, 장애 환불 후 이용 마지막 날
- 중복 결제 중 어느 건이 중복인지
- 미성년자 판단 시점(결제 당시)
- 이용 정지 계정에서 제외되는 환불과 유지되는 환불
- 요금제 변경 시 일할 계산과 프로모션 적용 여부
- 제3자 문의에 대한 안내 범위

### 남은 한계

- test는 20건(대화 7개)이다. 결과를 비교할 때 차이가 몇 건인지 함께 보고해야 한다.
- `partial_stt`(미확정 자막) 사례는 3건뿐이고 test에는 없다.
- `next_info`는 `identity`에 치우쳐 있고, `payment_date`와 `usage` 사례가 거의 없다.
- 상담 실무자 검토를 거치지 않았다.
