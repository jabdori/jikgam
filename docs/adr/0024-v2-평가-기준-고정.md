# 0024. v2 평가 기준 고정: 경계 정답 없이 검색 결과로 판정한다

> 처음 읽는다면: [전체 흐름 안내](../overview.md) · [용어집](../glossary.md)

- 상태: 채택
- 날짜: 2026-10-16
- 관련: `docs/evaluation-v2.md`, ADR 0006(평가 기준 사전 고정), 0015("예상되는 결과"), 0023(v2 원본 문서)

## 맥락

v2는 실제 규모의 문서(공백 제외 247,824자)에서 세 가지를 확인한다. 검색이 병목이 되는지, 새 방식이 단순한 방식보다 나은지, 문맥이 바뀌는 곳의 판단을 판별 모델로 바꿔도 되는지다. ADR 0006의 원칙대로 기준을 실행 전에 정하고 고정한다.

초안은 2026-10-16에 썼다. 구현을 보지 않은 에이전트가 검토했고, 높음 6건과 중간·낮음 여러 건을 반영해 다시 썼다(`PROGRESS.md`). 사용자가 초안을 확인하고 두 가지를 바꿔 승인했다.

초안의 질문 3은 경계 정답으로 판정했다. 사용자가 60줄 덩어리 15개(900줄)에 경계를 직접 표시하는 안이었고, 1~2시간이 든다. 모델의 제안을 고치는 방식은 쓰지 않았다. Gemini의 제안으로 정답을 만들면, Gemini로 자르는 (b)가 자기 답안으로 채점받는 셈이 되기 때문이다.

## 결정

1. **`docs/evaluation-v2.md`를 고정한다.** 이 결정 기록을 커밋할 때의 내용이다. 파일 해시는 아래 "고정한 파일"에 적는다. 고정한 뒤에 바꿔야 하면, 기존 문장을 지우지 않고 날짜, 이유, 바꾼 내용을 덧붙인다. 그리고 두 정의의 결과를 함께 보고한다.
2. **경계 정답을 만들지 않는다(사용자 결정).**
   - 질문 3은 세 조건으로 판정한다(§8.3). R4c의 근거 재현율@2,000이 R4보다 3%p 넘게 낮지 않아야 한다. 분할 비용은 (b)의 1/5 이하, 분할 시간은 (b) 이하여야 한다.
   - 분할 값(W, Cmax, 넘기는 맥락, θ)도 경계 F1 대신 근거 재현율로 고른다(§3.7, "분할 확인 재현율"). 구간 원문만 BM25로 색인해 val 질문으로 잰다.
   - 이유: RAG에서 분할의 목적은 검색이 근거를 찾게 하는 것이다. 이 조건은 초안에도 있었다. 사용자 시간은 사람만 할 수 있는 일(질문·정답 검토, 판정 확인)에 쓴다.
3. **참고 경계는 보고만 한다.**
   - 다른 계열 모델이 같은 경계 정의로 덩어리 15개를 표시한다. 각 방식과의 일치(F1, Pk, WindowDiff)를 보고하되, 판정과 값 고르기에는 쓰지 않는다(§2.2, §4.1).
   - 개발자는 이 파일을 test 실행 전까지 열지 않는다. 분할 프롬프트를 참고 경계에 맞추지 않으려는 것이다.
4. **다른 계열 모델은 Codex `gpt-6-astra`다(사용자 지정).**
   - 참고 경계 표시(§2.2)와 점검용 질문 50개 작성(§2.4)을 맡는다. Orca 작업 공간의 터미널에서 Codex CLI로 돌린다.
   - (b)의 Gemini, (c)의 판별 모델, 개발자(Claude)와 모두 계열이 다르다.
   - 초안에서는 참고 경계를 `gemini-3.1-pro-preview`가, 점검용 질문을 별도 Claude 에이전트가 맡았다.
5. **나머지는 초안대로다.**
   - 기준선 R0(조 단위 + 대체 규칙), 주 지표(근거 재현율@2,000), 답변 품질 판정(R0·R4, 3회 반복), 엔드투엔드 기준, §10의 1~7이 여기에 해당한다.
   - 판정 반복은 사용자 확인대로 3회를 유지한다.
6. **나중에 고정하는 것.** val에서 고르는 값, 프롬프트, 모델 버전 ID, 데이터·코드 해시다. val 조정이 끝나면 test 실행 전에 새 결정 기록으로 고정한다(§7).

## 대안

- **경계 900줄을 사용자가 직접 표시:** 자른 위치가 맞았는지를 사람 기준으로 볼 수 있다. 하지만 사용자 시간이 1~2시간 든다. 판정에 필요한 것은 검색 결과라서 택하지 않았다.
- **표본을 약 300줄로 줄여 직접 표시:** 30~40분이 든다. 덩어리가 5개 정도로 줄어 문서 묶음별 값의 확신이 낮다.
- **Gemini가 표시한 경계를 사람이 고치기:** (b)에 유리해진다(맥락 참고).

## 결과

- **한계:** 자른 위치가 맞았는지는 사람 기준으로 확인하지 않는다. 참고 경계도 모델이 표시한 것이라 정답이 아니다. 결과 보고에 이 한계를 적는다.
- **값 고르기의 치우침:** 분할 값을 재현율로 고르면, 많이 나눌수록 재현율이 오르는 쪽으로 골라질 수 있다. (c)의 θ는 이 지표로 직접 조정되는 값이기도 하다. 그래서 고른 값마다 구간 수와 길이 분포를 함께 적는다.
- **비용:** (b)를 val 후보 8가지마다 문서 전체에 돌려야 해서 분할 비용이 약 $7 늘었다. 합계는 약 $122~128이고, 그중 test 실행 한 번이 약 $65다(§9). Codex 사용량은 이 계산에 넣지 않았다.
- **사람이 할 일:** 질문·정답 검토 100개(약 1시간)와 판정 확인 30개(약 20분)다.
- **절차:** 데이터 만들기(약 $7~13)와 test 실행은 시작 전에 다시 확인받는다.
