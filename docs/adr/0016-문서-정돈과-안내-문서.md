# 0016. 문서 정돈: 고정 문서는 그대로 두고 안내 문서를 더한다

> 처음 읽는다면: [전체 흐름 안내](../overview.md) · [용어집](../glossary.md)

- 상태: 채택
- 날짜: 2026-10-14
- 관련: ADR 0006, 0014, 0015, `docs/evaluation.md`

## 맥락

최종 평가(ADR 0015)까지 마치는 동안 README와 문서가 측정 순서대로 쌓였다. 그래서 처음 보는 사람이 "보류용 시나리오", "정책 A/B/C", "판정 10번", "§7.3" 같은 내부 용어를 모르면 결과를 따라가기 어려웠다.

한편 평가 기준(`docs/evaluation.md`), 결정 기록(`docs/adr/`), 진행 기록(`PROGRESS.md`)은 측정의 근거다. 이 문서들의 본문을 다시 쓰면 측정 전에 정한 것과 결과를 본 뒤에 쓴 것을 구분할 수 없다.

## 결정

1. **고정 문서는 본문을 고치지 않는다.** `docs/evaluation.md`, `docs/adr/*`, `PROGRESS.md`에는 제목 바로 아래에 안내 문서로 가는 링크 한 줄과 빈 줄 하나만 더한다. 앞으로 보완이 필요하면 지금처럼 날짜를 붙여 덧붙인다. 결정 기록 목록에 0016 행을, 진행 기록에 이 작업의 날짜 항목을 덧붙인 것도 같은 방식이다.
2. **README를 처음 보는 개발자 기준으로 다시 짠다.** 순서는 무엇을 하는 시스템인지, 왜 이렇게 만들었는지(생성형 LLM의 지연·비용과 판별/생성 분리), 시스템 구조(그림 하나), 결과 요약, 한계, 실행 방법, 더 읽을 문서다. 수치와 사실은 바꾸지 않았다. 폴더별 설명 표는 `docs/overview.md` 7절로 옮겼다.
3. **안내 문서 두 개를 더한다.** `docs/overview.md`는 무엇을 만들었고 어떻게 쟀는지를 쉬운 말로 따라가는 전체 흐름 안내다. `docs/glossary.md`는 내부 용어를 풀어 둔 용어집이다.
4. **설계·엔진·학습·조직 B·조사 문서는 읽기 쉽게만 손댄다.** `docs/design.md`, `docs/engine.md`, `docs/training.md`, `docs/org-b.md`, `docs/research/korean-stt-tts.md` 맨 위에 "무엇을 다루고 누가 읽으면 되는지"를 두 줄로 넣었다. 긴 문단은 문장 경계에서 나눴다. 쉼표로 이어진 열거 네 곳(`docs/org-b.md` 세 곳, 조사 문서의 출처)은 같은 항목을 목록으로 바꿨다. 문장은 고치지 않았다.
5. **README와 안내 문서의 용어는 이렇게 바꿔 쓴다.** 고정 문서와 코드의 이름은 그대로 두고, 용어집에서 서로 이어 준다.

| 내부 용어 | README·안내 문서의 표현 |
|---|---|
| 보류용 시나리오 | 미공개 평가 시나리오 |
| 정책 A, B, C | 개선형 RAG 챗봇, 같은 엔진 + 생성형 LLM으로 판단, 같은 엔진 + Jev. 표 아래에 "정책 A, B, C"라는 이름을 함께 적는다 |
| 무효 제안 노출 | 이미 틀린 안내가 나간 횟수 |
| 근거 갱신 p95 | 조건 변경 후 근거를 다시 고르기까지(p95) |
| 판정 항목 10번, § 표기 | 용어집에서 풀어 쓴다 |

6. **윤문은 새로 쓰거나 고친 글에만 돌린다.** humanize-korean 2.3.2의 절차(정량 점수, 경로 결정, 윤문, 결정적 게이트)를 README, `docs/overview.md`, `docs/glossary.md`, 다섯 문서의 새 머리말에만 적용했다. 고정 문서와 기존 문서의 본문에는 돌리지 않았다. 네 입력 모두 정량 점수로 light 경로가 나왔다. 바뀐 것은 연결어미 뒤 쉼표 13곳을 지운 것과 `docs/overview.md`의 두 문장을 나눈 것이고, 머리말은 바뀌지 않았다. 게이트(문자 변경률, 수치·인용·말투 검사, 서법)는 모두 수렴이었다.

## 확인

- 고정 문서 18개: 더한 두 줄을 빼면 원래 파일과 바이트 단위로 같다.
- 다섯 문서: 공백, 목록 기호, 쉼표·마침표를 빼고 비교하면 원문과 같은 글자열이다(새 머리말 제외).
- 수치, 모델 이름, 인라인 코드(파일 경로 포함), 조항 ID: 고친 다섯 문서에서는 원래 값이 모두 남았다. 윤문 전후로는 값이 그대로다. README와 안내 문서의 값은 기존 문서(이전 README, 진행 기록, 결정 기록, 평가 기준 등)에 있는 값만 썼다. 예외는 새로 그린 구조도와, p95를 설명하는 예시 "요청 100개"뿐이고 둘 다 측정값이 아니다.

## ADR 0014의 해시

test 판별 실행의 `meta.json`은 고정 ADR의 해시를 `frozen_adr_sha256_16: e941d69f59074189`로 남겼다(`results/decisions/test/20261014T183544` 등). 이 값은 커밋 `2f79cad`의 `docs/adr/0014-엔진과-평가-설정-고정.md`다.

링크 줄을 더한 뒤 파일 해시는 `693afc5bb48f0d07`이다. 더한 3·4번째 줄을 빼면 원래 해시로 돌아온다.

```sh
sed '3,4d' docs/adr/0014-엔진과-평가-설정-고정.md | sha256sum | cut -c1-16   # e941d69f59074189
git show 2f79cad:docs/adr/0014-엔진과-평가-설정-고정.md | sha256sum | cut -c1-16
```

## 결과

- 처음 읽는 사람은 README → 전체 흐름 안내 → 용어집 순서로 읽으면 된다.
- 고정 문서의 기록은 그대로이고, 앞으로도 본문을 고치지 않는다.
- 용어가 두 벌(내부 이름, 쉬운 이름)이 된다. 둘의 대응은 용어집에 둔다.
