# 0001. 판별 데이터 형식

> 처음 읽는다면: [전체 흐름 안내](../overview.md) · [용어집](../glossary.md)

- 상태: 채택
- 날짜: 2026-10-12
- 관련: `docs/data-format.md`, `scripts/build_dataset.py`

## 맥락

같은 판별 데이터로 Jev 평가, 공개 모델 학습·평가, 생성형 LLM 기준선을 모두 돌려야 한다. 형식이 셋으로 갈라지면 같은 사례를 비교한다는 보장이 없다. 또 약관 문구는 검토 과정에서 계속 고쳐진다.

## 검토한 대안

- 사례마다 조항 본문을 직접 넣는다: 약관을 고칠 때 모든 사례를 손으로 고쳐야 하고, 문구가 사례마다 어긋날 수 있다.
- 평가 대상별로 다른 형식을 둔다: 변환 과정에서 차이가 생겨도 알아채기 어렵다.

## 결정

- 판별 데이터는 Hugging Face `typed-decisions` 데이터셋의 열 구성(`state`, `questions`, `gold`)을 따른다.
- 원본 사례에는 조항 ID만 적고, 빌드 스크립트가 `domain/org_a/terms.md`에서 본문을 채운다.
- 질문 문구는 `data/questions.json`에 버전과 함께 고정하고, 사례는 질문 ID만 고른다.

## 근거

Jev API와 Unsloth 판별 모델 학습 경로가 모두 상태와 타입이 정해진 질문을 입력으로 받는다. 하나의 형식으로 세 용도를 모두 처리할 수 있다.

## 예상되는 결과

- 약관을 고치면 빌드만 다시 하면 된다.
- Unsloth `build_dataset`이 이 형식을 그대로 받는지는 아직 확인하지 않았다. 다르면 내보내기 단계에서 변환한다.
