# 0002. 분할 방식과 test 고정

- 상태: 채택
- 날짜: 2026-10-12
- 관련: `data/splits.json`, `docs/data-format.md` 분할 절

## 맥락

한 대화의 앞뒤 시점이나 문구만 바꾼 변형이 여러 분할에 흩어지면 test 성능이 부풀려진다. 사례가 105건뿐이라 드문 실패 유형이 한 분할에 몰리기도 쉽다. 처음 무작위 배정에서는 test에 인계(handoff) 사례가 하나도 없었다.

## 검토한 대안

- 사례 단위 무작위 분할: 같은 대화가 train과 test에 함께 들어간다.
- 대화 그룹 단위 무작위 분할: 처음 배정에서 test에 인계 사례가 없었다.

## 결정

- 대화 그룹 단위로 train 60%, val 20%, test 20%를 목표로 나눈다.
- 드문 실패 유형 태그와 action 정답을 가진 그룹부터, 그 태그가 목표보다 가장 부족한 분할에 배정한다.
- 결과를 `data/splits.json`에 커밋하고, test에 배정된 그룹은 바꾸지 않는다. 이후 추가되는 그룹은 train과 val에만 넣는다.
- 배정 방식 변경은 분할을 처음 커밋하기 전, 어떤 평가도 하기 전에 했다.

## 근거

train 64 / val 21 / test 20(그룹 24 / 9 / 7)으로 나뉘었고, 인계 사례가 train 9 / val 2 / test 2로 퍼졌다. test 파일 sha256 앞 16자리는 `5251d7d814279bf4`다.

## 예상되는 결과

- test는 20건이라 결과 차이를 건수와 함께 보고해야 한다.
- `partial_stt` 사례는 test에 없다. 이 유형의 성능은 test로 주장할 수 없다.
