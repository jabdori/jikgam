## 맥락

음성 평가 기준(ADR 0017)과 정책 D(ADR 0018)를 정했고, 개발용 시나리오 s20, s21로 실행기와 지표를 점검했다(`results/voice/scenarios/smoke*`, `results/voice/smoke-replay-*`). 미공개 평가 시나리오로 한 번 평가하기 전에, 무엇으로 쟀는지 나중에 확인할 수 있게 설정을 고정한다(ADR 0014와 같은 방식).

실행 설정:

- 빠른 정정 1,000ms, 조용해진 뒤 700ms, 고객 말 상한 16, 시나리오별 3회
- VAD 끝 판정 0.5초, 확정 자막 기다리기 3초(C·D), D의 잠정 확정 자막 나이 상한 250ms, D의 동시 선판단 2개
- 모의 업무 API 실행 파일은 이 커밋의 `bizapi/`를 빌드한 것(`outputs/bin/jikgam-voice-api.exe`, `603f8b9f3e51a45f`)

## 결정: 실행 절차

1. `scripts/run_voice_eval.sh all`을 한 번 실행한다.
   - §3.1: 미공개 평가 시나리오 20개 × 3회를 정책 A·C·D 세 프로세스로 동시에 돌린다. 프로세스마다 모의 업무 API를 따로 둔다.
   - §3.2: 같은 시각에 개발용 재생 s20, s21 × 3회를 A → C → D 순서로 돌린다.
2. 결과를 본 뒤에는 기준(`docs/evaluation-voice.md`)과 이 설정을 바꾸지 않는다. 실행이 중간에 멈추면 멈춘 곳과 이유를 진행 기록에 남기고, 같은 설정으로 남은 부분만 다시 돌린다.
3. 판정은 `uv run python -m jikgam.voice.report`의 값을, 측정과 분리된 검토자가 원본 로그로 대조한 뒤 기록한다.

## 결과

- 네 프로세스가 같은 PC와 네트워크를 함께 쓴다. 지연에는 그만큼의 부하가 섞이며, 세 정책이 같은 조건이다.
- 예상 비용은 약 $25(고객 AI, 판정, 생성, STT·TTS 추정 포함)다.
