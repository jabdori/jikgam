# 0018. 음성 정책 D: 실시간 자막으로 미리 판단하고 말이 끝나면 바로 확정한다

> 처음 읽는다면: [전체 흐름 안내](../overview.md) · [용어집](../glossary.md)

- 상태: 채택
- 날짜: 2026-10-15
- 관련: `docs/evaluation-voice.md` §9, `docs/evaluation.md` §3.4, `docs/engine.md` §3.1, ADR 0017

## 맥락

ADR 0017은 음성에서 정책 A와 C만 비교하기로 했다. 개발용 점검에서 C의 근거 갱신은 약 1.1~1.2초였고, 그중 약 0.8초가 확정 자막을 기다린 시간이었다. 사용자는 실시간 자막으로 바로 판단하는 최근 방식을 지적했다. 2026년 음성 봇 런타임(LiveKit 선제 생성, Deepgram Flux의 이른 말 끝 신호)도 확정 전에 LLM 작업을 먼저 시작한다(`docs/evaluation-voice.md` §9.1).

## 결정

1. 정책 D를 만들어 A·C와 같은 조건에서 비교한다. D는 C에 세 가지를 더한다. 실시간 자막마다 첫 판별을 미리 돌려 두고, VAD가 말 끝을 판정하면 마지막 실시간 자막으로 잠정 확정하고, 확정 자막이 다르면 새 발화로 다시 판단한다.
2. 실시간 자막에 숫자가 있으면 잠정 확정하지 않는다. 번호 인식 오류로 본인 확인이 실패하면 되돌릴 수 없기 때문이다.
3. 선판단은 세션 상태를 바꾸지 않는다. 나중의 첫 판별이 같은 상태(같은 판별 입력과 질문)일 때만 그 결과를 쓴다. 그래서 선판단이 틀려도 엔진의 판단 내용은 C와 같다. 빨라질 뿐이다.
4. 판정 기준은 ADR 0017과 같다(§5의 세 조건을 D와 A에 적용). D와 C의 차이와 늘어난 호출·비용은 보고만 한다.
5. 엔진 코드는 채팅 동작이 바뀌지 않게 더한다. 선판단은 음성 계층이 부를 때만 돈다.

## 대안

- **잠정 확정 없이 선판단만:** 확정 자막 대기(약 0.5초)가 그대로 남아 줄일 수 있는 시간이 작다.
- **실시간 자막마다 버전을 올리기:** 말하는 도중에 버전이 계속 올라 진행 중인 작업이 계속 취소된다. 근거 화면도 흔들린다.
- **VAD 끝 판정 시간(0.5초)을 줄이기:** 모든 정책이 함께 쓰는 음성 계층 설정이고, 문장 사이 쉼에서 발화가 더 자주 나뉜다. 이번에는 바꾸지 않는다.

## 결과

- 잠정 문장과 확정 자막이 다르면, 잠정 문장으로 만든 답이 이미 재생되기 시작했다가 끊길 수 있다. 이 경우는 무효 노출로 셀 수 있으며 그대로 보고한다.
- 판별 호출이 늘어난다. 늘어난 수와 비용을 보고한다.
