# 0022. 화면은 디자인 하네스를 통과해야 완료로 본다

> 처음 읽는다면: [전체 흐름 안내](../overview.md) · [용어집](../glossary.md)

- 상태: 채택
- 날짜: 2026-10-15
- 관련: ADR 0021, `docs/design/README.md`, `docs/design/forbidden-terms.md`, `docs/design/components.md`

## 맥락

화면 여덟 개를 두 테마로 만든다(ADR 0021). 화면마다 색, 간격, 용어가 조금씩 달라지거나, 고객사 화면에 엔진 수치가 섞이거나, 시안의 숫자가 코드에 그대로 남는 일을 사람이 눈으로 다 잡기는 어렵다.

그래서 화면을 만들기 전에 이런 문제를 검사로 잡는 장치(디자인 하네스)를 먼저 만든다.

## 결정

하네스는 일곱 가지로 이루어진다. 1~4는 `uv run pytest`가 돌리고, 5·6은 브라우저(Playwright, Chromium)가 필요해 `uv run python scripts/ui_check.py`가 돌린다. 둘 다 통과하고 7의 지적을 처리해야 화면을 완료로 본다.

1. **토큰 하나:** 색, 글꼴, 글자 크기, 간격, 모서리, 테두리 굵기는 `jikgam/web/static/tokens.css` 한 곳에서만 정한다.
   - 고객사 테마(`data-theme="saas"`, 밝은 톤)와 관리 테마(`data-theme="admin"`, 어두운 톤)는 같은 토큰 이름에 값만 다르다.
   - 린트(`scripts/lint_design.py`, `tests/test_design_lint.py`)는 토큰 파일 밖의 CSS, JS, 화면 코드에서 다음을 찾으면 실패한다.
     - 색상값(`#hex`, `rgb()`, `hsl()`, 색 이름)
     - px 값
     - `style` 속성
   - 예외는 자료에서 오는 막대 길이·위치·색 진하기다. 컴포넌트의 두 함수(`_style_vars`, `_alpha`)만 `style="--pct: …%"`처럼 사용자 정의 속성(`--pct`, `--at`, `--len`, `--alpha`)으로 쓴다.
2. **공용 컴포넌트:** 셸(메뉴·상단바), 카드, 표, 배지, 지표 칸, 빈 상태, 드로어를 `jikgam/web/ui/components.py`와 `components.css`에 둔다.
   - 화면 코드(`jikgam/web/saas/`, `jikgam/web/admin/`)는 컴포넌트와 숫자 형식 함수만 쓴다. HTML을 만드는 낮은 수준 함수(`jikgam/web/ui/html.py`)를 직접 부르면 린트가 실패한다.
   - 새 모양이 필요하면 컴포넌트를 더하고, 이유를 `docs/design/components.md`에 적는다.
3. **고객사 화면 문구 검사:** 금지어 목록은 `docs/design/forbidden-terms.md`의 표에 둔다. 검사가 이 표를 직접 읽는다.
   - `tests/test_saas_terms.py`는 고객사 경로 전부를 테스트 자료로 렌더링한 HTML을 검사한다. 보이는 글자, 사용자에게 보이는 속성(`title`, `aria-label`, `placeholder`, `alt`, `value`), 실시간 갱신 조각이 대상이다.
   - `ui_check.py`는 실제 결과 파일로 띄운 화면에서 스크립트 실행 뒤의 글자(`innerText`)를 같은 목록으로 검사한다.
4. **숫자 출처 검사:** 두 겹으로 검사한다.
   - **정적 검사:** 화면 코드와 컴포넌트의 문자열 상수에 숫자를 쓰면 린트가 실패한다. 숫자 상수는 0과 1만 쓴다. 쪽당 행 수, 정답 일치도의 k 같은 값은 `jikgam/web/settings.py`에 이름을 붙여 두고 `docs/design/data.md`에 적는다.
   - 숫자가 아니라 이름인 표기는 예외다: 제목 태그 이름(`h1`~`h6`), 컴포넌트의 구조 값(`tabindex`, 문자 집합, 제목 수준 기본값, 백분율 100), 지표·단위 이름(`p95`, `1회`, `1M`). 예외 전체는 `docs/design/README.md`의 표에 있다.
   - **정적 검사(계속):** HTML을 만드는 함수는 숫자를 그대로 받지 않는다. 화면의 숫자는 형식 함수(`jikgam/web/ui/fmt.py`)를 거쳐 `data-num` 표시가 붙은 요소로만 나간다. JS는 글자를 만들지 않고, 서버가 만든 HTML 조각과 속성만 다룬다.
   - **동적 검사:** `tests/test_number_source.py`는 화면마다 테스트 자료 두 벌로 렌더링한다. 둘째 벌은 첫째 벌의 건수, 금액, 날짜, 시각, 확률, 지연, 비용을 모두 바꾼 것이다. 두 벌의 `data-num` 값이 하나라도 겹치면 실패한다(자료와 무관하게 늘 같은 숫자로 본다).
   - 결과 자료가 아닌 숫자는 형식 함수에 종류를 붙여 동적 검사에서 뺀다: 목록의 몇 번째(`index`), 순위(`rank`), 재생 띠 눈금(`axis`), 평가 기준 문서의 사전 기준 값(`criterion`).
5. **스크린샷:** 화면마다 1440px와 390px 폭으로 전체 페이지를 찍어 `docs/design/screens/`에 남긴다.
   - 찍을 때마다 이전 파일과 화소를 비교해 바뀐 비율을 `docs/design/screens/changes.md`에 적는다.
   - 실시간 통화는 재생 피드의 시각을 고정해 찍는다.
   - 글꼴은 외부에서 받지 않고 시스템 글꼴을 쓴다. 외부 요청 없이 같은 결과를 내기 위해서다.
6. **접근성:** axe(axe-core 4.12.1)로 화면마다 두 폭을 검사해 심각(serious) 이상 위반이 0건이어야 한다. 화면마다 정한 주요 흐름을 키보드(Tab, Enter, Space, Escape)만으로 끝까지 해 보고, 포커스가 보이는지 확인한다. 문서가 가로로 넘치지 않는지도 두 폭에서 본다.
7. **독립 리뷰:** 화면이 끝날 때마다 구현을 보지 않은 별도 에이전트가 스크린샷과 시안만 보고 아래 기준으로 검토한다. 지적과 처리 결과는 `docs/design/reviews/<화면>.md`에 남긴다.
   - 이 요소를 보고 사용자가 내릴 결정이 있는가. 없으면 뺀다.
   - 같은 숫자나 정보가 두 곳 이상에 반복되는가.
   - 모든 제목 아래에 설명 문구를 붙이거나, 장식용 그라데이션·아이콘·배지를 남발했는가.
   - 시안 및 다른 화면과 간격, 정렬, 용어가 일관적인가.
   - 고객사 화면에 내부 관리용 정보가 섞였는가.

## 검토한 대안

- **Jinja 같은 템플릿 엔진:** 템플릿 안의 숫자와 색을 따로 파싱해야 한다. 화면 코드를 Python 함수로 두면 AST로 문자열 상수를 검사하고, 숫자를 형식 함수 밖으로 내보내지 못하게 막을 수 있다.
- **화면을 브라우저에서 JS로 그린다:** 금지어·숫자 검사에 브라우저가 늘 필요하다. 서버에서 HTML을 만들고 JS는 동작만 붙이면 대부분의 검사를 브라우저 없이 빠르게 돌릴 수 있다.
- **외부 스타일 린터(stylelint):** 이 저장소에 Node 의존성이 생긴다. 지킬 규칙이 몇 개뿐이라 Python 스크립트로 충분하다.
- **Playwright 최신판(1.64):** 이 PC에 받아 둔 Chromium(빌드 1243)과 맞지 않아 브라우저를 새로 받아야 한다. 받아 둔 브라우저와 맞는 1.63.0으로 고정한다.

## 예상되는 결과

- 화면을 고칠 때마다 스크린샷이 바뀌고, 바뀐 비율이 기록된다.
- 시안에 없는 모양을 더하면 컴포넌트 문서가 함께 바뀐다.
- 하네스는 일관성과 문구를 잡지만, 화면이 업무에 맞는지는 독립 리뷰와 사용자의 확인으로만 알 수 있다.
