# 0003. 고객 진술과 시스템 기록의 구분, 기록 우선

- 상태: 채택
- 날짜: 2026-10-12
- 관련: `docs/data-format.md` 라벨 기준, `docs/labeling-review.md`

## 맥락

고객은 결제일, 결제 횟수, 이용 여부를 잘못 기억하거나 다르게 주장한다. 고객 말을 그대로 사실로 확정하면 금액과 자격 판단이 틀린다. 반대로 이미 조회된 기록이 있는데 계속 고객에게 다시 물으면 상담이 길어진다. 라벨 검토에서 이 기준이 작성자마다 갈렸다(g026-2, g027-2, g040-1).

## 검토한 대안

- 고객 진술을 우선하고 기록과 다를 때 다시 묻는다: 기록이 있는 경우에도 확인 질문이 반복된다.
- 진술과 기록을 구분하지 않는다: 금액 계산에 확인되지 않은 값이 들어간다.

## 결정

- 상태에서 고객 진술로만 알게 된 값에는 `(고객 진술)`을 붙이고, 시스템 조회 값은 그대로 쓴다.
- 금액 계산과 접수에 쓰는 사실은 시스템으로 확인된 것만 확정으로 본다.
- 조회 기록이 이미 있으면 고객이 다르게 주장해도 기록을 근거로 안내하고 다시 묻지 않는다.

## 근거

라벨 검토에서 작성자와 독립 검토자가 갈린 항목을 이 기준으로 판정했고, 같은 유형의 다른 사례와도 일관된다.

## 예상되는 결과

- 엔진의 상태 구조가 진술과 조회를 필드 단위로 구분해야 한다.
- 고객이 기록과 다른 주장을 하면 `condition_changed`는 true지만 처리 결과는 바뀌지 않는다. 시나리오 s03, s23이 이 경우다.
