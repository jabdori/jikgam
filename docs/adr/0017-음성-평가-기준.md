# 0017. 음성 평가 기준: 정책 A와 C를 음성으로 비교한다

> 처음 읽는다면: [전체 흐름 안내](../overview.md) · [용어집](../glossary.md)

- 상태: 채택
- 날짜: 2026-10-14
- 관련: `docs/evaluation-voice.md`, `docs/evaluation.md` §3.2·§3.3·§4·§5.1·§7.3, `docs/voice.md`, ADR 0008, 0013, 0015

## 맥락

ADR 0015는 주장 2가 채팅 합성 대화의 결과이며 음성은 재지 않았다는 한계를 남겼다. 음성은 답을 되돌릴 수 없고, 인식·합성 시간과 인식 오류가 더해지며, 고객이 답 도중에 끼어든다. 채팅의 결론이 음성에서도 유지되는지 따로 재야 한다.

새 평가이므로 기준을 실행 전에 정하고 고정한다. 채팅 결과와 `docs/evaluation.md`는 바꾸지 않는다.

## 결정

1. **기준 문서를 따로 둔다.** `docs/evaluation-voice.md`에 음성 평가의 비교 대상, 실행 방식, 지표, 성공 기준을 적고, 음성으로 A·C를 돌리기 전에 이 ADR로 고정한다.
2. **정책 A와 C만 비교한다.** B는 채팅에서 구조 효과와 판별 속도 효과를 나누는 역할을 마쳤다. D(미확정 자막 선판단)는 구현되지 않았다. 이번 평가는 D가 아니라 C의 음성 실행이다.
3. **음성 계층은 공통 기능과 엔진 기능을 나눈다.**
   - 공통 기능: 한 번에 하나씩 재생, 고객이 말하는 중에는 시작하지 않기, 끼어들면 멈추기. 흔한 음성 봇의 기능이라 두 정책 모두에 둔다.
   - 엔진 기능: 버전이 지난 답을 버리거나 끊기, 확정 자막 기다리기. 대화 버전 원칙의 일부라 C에만 둔다.
   - A에 엔진 기능을 주면 A가 엔진 구조의 이점을 받아 비교가 흐려진다. 공통 기능까지 빼면 A가 실제 음성 봇보다 약해진다.
4. **판정은 미공개 평가 시나리오 20개 × 3회의 음성 실행으로 한다.**
   - AI 고객의 문장을 TTS로 읽어 넣는다.
   - 조건 변경은 채팅과 같은 1,000ms 빠른 정정으로 보낸다. 채팅 결과와 같은 정의로 비교하려는 것이다.
   - 고객이 답을 듣다가 끼어드는 경우는 개발용 녹음 재생(s20, s21)으로 따로 재고, 보고만 한다.
5. **성공 기준은 채팅 §7.3과 같은 값이다.** 음성 결과를 보기 전에 정했고, 돌리지 않는 B와의 비교 조건만 뺐다. 음성에 맞춰 기준을 새로 고르면 결과를 보고 고른 것과 구분하기 어렵기 때문이다.
6. **녹음을 남긴다.** 세션마다 실제로 재생된 응답 음성을 스테레오 WAV(오른쪽 채널)로 남기고, 녹음 시작 시각·해시·길이를 세션 로그에 적는다. 녹음 파일은 저장소에 넣지 않는다. 다음 단계의 통화 리플레이에서 쓴다.

## 대안

- **고정 녹음만 쓰기:** 두 정책이 완전히 같은 음성을 듣는 장점이 있다. 하지만 고객이 상담원 답에 반응하지 못해 시나리오 통과를 판정할 수 없다. 보조 결과로만 쓴다.
- **조건 변경을 끼어들기로만 보내기:** 고객이 답을 들은 뒤 정정하면 A의 이전 답 생성은 이미 끝나 있어, 이미 틀린 안내가 나갈 틈이 거의 없다. 채팅 주장 2와 같은 상황을 재지 못한다.
- **음성 전용 새 기준:** 음성 결과를 본 적이 없어 근거가 없다. 같은 기준을 쓰고, 음성에서 달라지는 값(첫 음성, 재생 시간, 끼어들기)은 보고만 한다.

## 결과

- 음성 결과는 `results/voice/` 아래 새 경로에 두고, 채팅 결과 표는 바꾸지 않는다.
- 실행 전에 코드·설정·데이터 해시를 새 ADR로 고정한다.
