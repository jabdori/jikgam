# 0021. 웹 화면을 고객사 콘솔과 관리 콘솔로 나눈다

> 처음 읽는다면: [전체 흐름 안내](../overview.md) · [용어집](../glossary.md)

- 상태: 채택
- 날짜: 2026-10-15
- 관련: ADR 0005(이 결정으로 대체), ADR 0007, ADR 0022, `docs/design/README.md`, `docs/design/data.md`

## 맥락

ADR 0005는 웹 화면을 상담 콘솔, 턴 상세 타임라인, 평가 대시보드 세 개로 한정했다. 세 화면 모두 엔진 내부 정보(판별 지연, 조항 확률, 자막 확정 시각)와 상담 운영팀이 볼 정보(대화, 처리 결과)를 한 화면에 섞어 보여 준다.

이번 단계는 이것을 두 제품으로 나눈다.

- **고객사 콘솔:** 상담 운영팀이 매일 쓰는 화면이다. 결과와 행동만 보여 준다.
- **관리 콘솔:** 직감 팀 내부용이다. 모델, 평가, 진단을 다룬다.

화면 시안은 사용자가 `docs/design/mock/`에 넣었다. 시안의 숫자는 옮겨 적지 않고 결과 파일에서 읽는다.

## 결정

1. **경로**
   - 고객사 콘솔은 `/app/` 아래에 둔다. 화면은 실시간 통화, 통화 기록, 운영 리포트, 지식·정책, 연동이다.
   - 관리 콘솔은 `/admin/` 아래에 둔다. 화면은 모델·벤치마크, 통화 리플레이, 고객사 관리다.
   - 기존 세 화면(`/console`, `/timeline`, `/dashboard`)과 그 정적 파일, 콘솔의 실시간 엔진 세션(`jikgam/web/live.py`)은 없앤다. 엔진과 직접 대화하는 일은 명령줄(`jikgam.engine.chat`)로 한다.
   - 계산 함수(`jikgam/web/dashboard.py`, `timeline.py`, `view.py`)는 남겨 새 화면의 자료로 다시 쓴다.
2. **권한**
   - 계정은 저장소 밖 환경 파일(`.env` 또는 환경 변수 `JIKGAM_WEB_ACCOUNTS`)에 둔다. 역할은 둘이다. `admin`은 관리 콘솔을, `tenant`는 자기 조직 하나의 고객사 콘솔을 연다.
   - 관리자도 고객사 콘솔을 열지 않고, 고객사 계정은 관리 콘솔을 열지 않는다. 두 제품을 한 계정에서 섞지 않기 위해서다.
   - 인증은 HTTP 기본 인증이다. 계정 설정이 없으면 서버를 띄울 때 임의 비밀번호를 만들어 터미널에만 보여 준다.
   - 로컬 시연용 인증이며 운영용 인증이 아니다. 로그인 화면과 계정 관리 화면은 만들지 않는다.
3. **시각 구분:** 같은 토큰 이름을 쓰고 값만 다르게 둔다. 고객사 콘솔은 밝은 테마, 관리 콘솔은 어두운 테마에 ADMIN 표시를 단다(ADR 0022).
4. **고객사 콘솔의 자료**
   - 조직마다 어떤 실행 폴더를 통화 기록으로 보일지 `config/web/tenants.toml`이 정한다. 제품의 방식인 정책 C·D 실행만 넣는다. 기준선(정책 A·B) 실행은 관리 콘솔에서만 보인다.
   - 미공개 시나리오 실행은 기존 규칙대로 `--allow-holdout`일 때만 연다(`data/scenarios/HOLDOUT.md`). 화면 스크린샷과 독립 리뷰에는 개발용 시나리오 실행만 쓴다. 미공개 시나리오의 대화 내용을 더 퍼뜨리지 않기 위해서다.
   - 실시간 통화는 기록된 합성 통화를 원래 시각대로 다시 흘려 보여 준다(재생 피드). 엔진과 외부 API를 부르지 않으므로 비용이 들지 않는다.
     - "상담사가 넘겨받기"를 누르면 그 통화의 재생을 멈추고 상담사 응대로 표시한다.
     - 실제 통화(엔진 세션)를 이 화면에 붙이는 경로는 이번에 만들지 않았다. 붙이면 같은 버튼이 엔진의 상담사 인계(`Session.request_handoff`)를 불러야 한다.
     - 화면에는 기록을 다시 재생하는 데모 자료라고 적는다.
   - 엔진 내부 용어와 수치는 고객사 화면에 넣지 않는다. 금지어 목록과 검사는 ADR 0022를 따른다.
   - 화면 수치의 정의와 계산 함수는 `docs/design/data.md`에 적는다.
     - "고객이 요청을 바꾼 상담"은 시나리오가 조건 변경으로 표시한 고객 발화가 있는 상담이다.
     - "잘못된 안내"는 평가의 무효 제안 노출(`docs/evaluation.md` §3.3)과 같은 함수로 센다.
     - 합성 상담에서는 시나리오의 표시를 쓴다. 실제 운영이라면 사람이 검토해 표시해야 한다.
5. **관리 콘솔의 자료와 동작**
   - **모델 등록:** 어댑터 종류와 엔드포인트만으로 등록한다. 등록은 `config/decision_models.d/<이름>.toml` 파일 하나를 쓰는 것이다.
     - `jikgam/decision/registry.py`는 기존 `config/decision_models.toml`과 이 폴더를 함께 읽는다. ADR 0007의 공통 인터페이스(`decide`)를 넓히는 것이고, 새 모델을 더할 때 코드를 바꾸지 않는다.
     - 어댑터는 세 종류다. 판별 API와 로컬 서버는 기존 Jev 형식 클라이언트를 쓰고, OpenAI 호환 생성형은 이번에 클라이언트 하나를 더한다. 이 클라이언트는 생성형 LLM 판단과 같은 프롬프트를 쓴다.
   - **벤치마크 실행:** 화면에서 실행할 수 있는 것은 판별 val 분할, 개발용 시나리오, 개발용 음성 재생, 부하 측정이다.
     - 기존 실행기를 하위 프로세스로 부른다. 시나리오 실행기(`jikgam.sim.runner`)와 음성 재생기(`jikgam.voice.replay`)에 판별 백엔드를 바꾸는 `--decision-backend` 옵션을 더했다. 옵션이 없으면 지금과 같이 조직 설정의 백엔드를 쓴다.
     - 부하 측정 실행기(`jikgam.eval.load`)는 이번에 새로 만들었다. val 사례를 동시 요청 여러 개로 정한 시간 동안 보낸다.
     - test 분할과 미공개 시나리오는 화면에서 실행할 수 없다. 설정을 고정한 뒤 한 번만 평가한다는 고정 규칙 때문이다. 이미 있는 test·미공개 결과는 읽어서 보여 준다.
     - 실행 전에 예상 호출 수와 예상 비용을 보여 주고, 확인한 뒤에만 실행한다.
   - **통화 리플레이:** 음성 실행의 이벤트 로그와 녹음을 쓴다. 정답 일치도의 k는 4다(`docs/design/data.md`). 개발용 시나리오의 정답 조항 수 중앙값이 4이고, 엔진의 검색 시작 조항 수(`seed_top_k`)도 4다.
   - **고객사 관리:** 조직 설정 파일, 조직 B 기록(`docs/org-b.md` §5), 저장소 파일의 존재로 채운다.
6. **ADR 0005 처리:** 0005는 고치지 않는다. `docs/adr/README.md` 목록의 상태만 "대체됨(0021)"으로 바꾼다. 0001~0016을 고치지 않는다는 이번 단계 규칙을 지키면서 기존 관례도 따르기 위해서다.

## 검토한 대안

- **한 앱에 역할별 메뉴만 숨긴다:** 경로가 같으면 고객사 화면에 내부 정보가 섞여도 검사로 잡기 어렵다. 경로를 나누면 금지어 검사를 고객사 경로 전체에 걸 수 있다.
- **실시간 통화를 실제 엔진 세션으로만 채운다:** 화면을 열 때마다 판별·생성 API 비용이 들고, 스크린샷이 실행마다 달라진다.
- **화면에서 test 분할 벤치마크를 허용한다:** 튜닝 중에 test를 보게 되어 고정 규칙을 어긴다.

## 예상되는 결과

- 화면은 여덟 개가 된다. 디자인 하네스(ADR 0022)를 통과하지 않은 화면은 완료로 보지 않는다.
- 로그인 화면, 계정 관리, 고객사 콘솔의 문서 업로드 처리(텍스트 추출부터 게시까지)는 이번에 만들지 않는다.
- 폼을 받기 위해 웹 의존성에 `python-multipart`를 더했다.
  - 지식·정책 화면은 v1 약관을 지금 상태대로 보여 준다. 실제로 하지 않은 처리 단계는 "적용 안 함"으로 표시한다.
  - 처리 단계의 백엔드는 v2(법령 문서 검색)에서 붙인다.
