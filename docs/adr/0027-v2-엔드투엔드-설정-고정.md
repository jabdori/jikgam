# 0027. v2 엔드투엔드 설정 고정

> 처음 읽는다면: [전체 흐름 안내](../overview.md) · [용어집](../glossary.md)

- 상태: 채택
- 날짜: 2026-10-18
- 관련: `docs/evaluation-v2.md` §2.5·§4.3·§4.4(2026-10-18 보완)·§4.5·§8.4(2026-10-18 보완), `docs/evaluation.md` §3.2·§3.3·§4.1, ADR 0014(v1 설정 고정), 0025, 0026

## 맥락

ADR 0025에서 엔드투엔드(미공개 시나리오 12개 × 3회)를 다음 일로 미뤘다. v2 test는 끝났다(ADR 0026). 엔드투엔드 기준은 2026-10-16에 `docs/evaluation-v2.md` §4.4와 §8.4에 고정돼 있다.

| 조건 | 기준 |
|---|---|
| 통과율 | R4가 R0보다 5%p 넘게 낮지 않다 |
| 근거 없는 주장 비율 | R4가 R0 이하다 |
| 근거 갱신 | R4의 p95가 500ms 이하다 |

미공개 실행 전에 한 일은 다음과 같다. 모두 개발용 시나리오(sv01~sv12)와 합성 입력으로 했다.

- **판정 도구(Codex `gpt-6.1-sol`):**
  - 노출 제안의 주장 판정(`jikgam.v2.e2e_claims`)
  - §8.4 보고기(`e2e_report`)
  - 실행·원본 보존·공개 사본 명령(`e2e_run`, `e2e_logs`)
  - 표준약관 문장 검사(`terms_scan`)
  - 실행 계약 잠금(`e2e_contract`, `freeze --e2e`)
  - 사람 확인 화면(`e2e_check`)
- **개발용 재측정:**

  | 실행 | 통과 R0 / R4 | 근거 갱신 p95 R0 / R4 |
  |---|---|---|
  | -1(법령 판별 질문 전) | 1/11 / 0/11 | |
  | -2(법령 판별 질문 뒤) | 3/11 / 3/11 | |
  | -3(검색어 규칙 뒤) | 1/11 / 2/11 | 320ms / 413ms |

  - -3의 근거 없는 주장은 R0 233개 중 1개, R4 240개 중 2개다.
- **코드 리뷰(Codex `gpt-6-astra`):** 1차 7건(높음 4), 재확인 5건(높음 1), 마지막 확인 1건(낮음). 모두 고쳤다(아래 정의).
- **미공개 시나리오 기대값 대조:**
  - 별도 도출자(Codex `gpt-6-astra`)가 기대값을 가린 묶음만 보고 기대값을 다시 도출했다.
  - 보관자(Codex `zai/glm-5.3`)가 84칸을 대조했다.
  - 불일치 44칸 가운데 36칸은 작성자 값을 유지하고 8칸을 고쳤다. 8칸 모두 본인 확인 조항 누락이다.
  - 코디네이터는 개수만 받았다(`5fc1096`, `data/scenarios/HOLDOUT_V2.md` 보완 절).

## 결정: 엔진 변경(개발용 시나리오로만)

- **법령 판별 질문과 생성 규칙 20:** 법령 판별 질문(`law_applies`)과 생성 규칙 20은 이미 있었다(`aa7c469`). 고객이 법령을 물으면 법령 근거로 답한다.
- **법령 검색어:** 법령 묶음을 켠 세션만, 고객 발화 누적에 기존 의도·표현 확장을 더한 검색어를 쓴다(`config/v2/law.toml` `query_scope = "all"`).
  - 유료 호출 없이 개발용 근거 이벤트에서 검색어 규칙 6개를 비교했다.
  - 채택 기준은 비교 전에 정했다. 두 프로필 모두 정답 법령을 덮는 비율이 오르고, 어느 쪽도 떨어지지 않아야 한다.
  - 이 기준을 만족한 규칙은 이것 하나였다(R0 45/167 → 65/167, R4 68/165 → 74/165).
  - 구간 세트, 구간 정보, 임베딩, 결합, 후보 수 8, 판별 질문, 임계값 0.5는 바꾸지 않았다.
- **기록:** 생성 요청마다 생성 모델에 넘긴 입력 전체를 로그에 남기고, 제안의 출처(모델 생성, 검사 뒤 고정 문구, 엔진 오류 문구)를 남긴다. 동작은 바꾸지 않는다.
- **바꾸지 않은 것:** 법령 묶음을 끈 세션(v1 채팅·음성)의 동작은 그대로다. 리뷰어가 변경 전후를 같은 가짜 판별·생성기로 비교해 확인했다.

## 결정: 실행 전에 정한 계산 정의

기준 문서가 정하지 않았거나 코드와 달랐던 것을 실행 전에 정한다.

- **유효 실행:** 고객 AI 지시 준수가 '준수'로 판정된 실행만 집계한다.
  - 무효와 준수 미판정은 따로 센다.
  - 준수 미판정이 남으면 통과율, 근거 없는 주장 비율, 근거 갱신 조건을 판정 보류로 둔다.
- **통과율:** `docs/evaluation.md` §4.1이다. 항목 10은 §4.4대로 조직 A 조항 id와 법령·고시 정답 근거를 모두 덮어야 한다.
  - AI 판정기 응답에 필수 항목이 빠지거나 형식이 틀리면 §4.5대로 2·4·8초 뒤 최대 3번 다시 부른다.
  - 그래도 빠진 항목은 판정 불가다. 판정 불가가 남은 세션이 있으면 통과율 조건은 판정 보류다.
- **R4 − R0 통과율:**
  - 구간은 시나리오 단위 짝지은 부트스트랩이다(10,000회, seed 20261016). 뽑힌 시나리오의 두 구성 유효 반복을 모두 쓴다.
  - **비열등:** 점추정 −5%p 이상
  - **"나아졌다":** 점추정 +10%p 이상이고 95% 구간 아래 끝이 0보다 클 때만이다(§8 "개선 주장은 95% 구간으로 판정").
- **근거 없는 주장 비율(§4.4, §4.3을 노출된 제안에 적용):**
  - **판정 단위:** 노출된 제안 하나에 판정 호출 하나다.
  - **판정 모델:** `gemini-3.1-pro-preview`이고, `jikgam/v2/answer.py` 판정 지시의 근거 유무 부분만 쓴다(정답 판정 없음).
  - **판정 입력:** 그 제안을 만든 생성 요청에 넘긴 입력 전체(조항 글, 견적, 업무 API 결과, 계획, 대화)다. §4.3의 "생성에 넘긴 글"이다.
    - 처음 만든 도구는 인용 조항 글만 줘서, 업무 API에서 온 금액·상태 주장을 근거 없음으로 셌다. 개발용 -2에서 R0 33%, R4 42%였다.
    - 정의대로 고친 -3에서는 0.4%, 0.8%였다.
  - **고정 문구:** 검사 실패 뒤 고정 문구와 엔진 오류 문구는 생성 모델이 만든 글이 아니어서 비교할 생성 입력이 없다. 그래서 모집단에서 빼고 수를 따로 보고한다.
  - **판정 실패:** 판정 응답의 구조가 틀리면 §4.5대로 다시 부른다. 끝내 실패한 제안이 남으면 이 조건은 판정 보류다.
  - **계산:** 비율은 유효 실행의 모든 주장을 합친 분모로 낸다. 조건은 점추정 R4 ≤ R0이고, 시나리오 단위 짝지은 구간을 함께 보고한다.
- **근거 갱신:** `docs/evaluation.md` §3.2와 `jikgam.sim.metrics`의 정의다. 미갱신은 무한대로 넣는다. 조건은 R4 p95 ≤ 500ms다.
- **사람 확인:** 실행 뒤 사용자가 한 화면에서 두 가지를 확인한다. 화면에는 모델 판정과 구성(R0/R4, 구간 id의 구성 단서)이 보이지 않는다.
  - 노출 제안의 주장 30개(근거 있음/없음): 일치율 0.80 미만이면 근거 없는 주장 비율 조건이 판정 보류다.
  - AI가 판정한 시나리오 항목 10개(통과/실패): 일치율 0.80 미만이면 통과율 조건이 판정 보류다.
- **반복과 순서:** 시나리오별 3회다. R0 3회를 먼저 돌리고 R4 3회를 돌린다.
  - 두 구성의 실행 계약(아래)은 법령 프로필만 다르다.
  - 동시에 돌리지 않는다. 지연 측정이 서로 간섭하지 않게 하려는 것이다.

## 결정: 실행 절차

1. 고정 커밋에서 새 작업 사본을 만든다. 저장소 밖 자료(`data/v2/local/`)와 키 파일(`.env`)을 복사한다.
2. `jikgam.v2.freeze verify --adr 0027 --e2e`가 해시와 계약을 확인한다.
3. `jikgam.v2.e2e_run`으로 R0(시나리오 12개 × 3회)를 돌린다. 이 명령이 모의 업무 API 빌드·기동부터 원본 보존, 공개 사본, 검사까지 한다. 이어서 R4를 같은 방식으로 돌린다.
4. 주장 판정(`e2e_claims`), 보고(`e2e_report`), 사람 확인 화면(`e2e_check build`), 표준약관 검사(`terms_scan`) 순서로 한다.
5. 측정과 분리된 검토자(Codex `zai/glm-5.3`)가 비공개 원본에서 §8.4 수치를 따로 계산해 대조한다.
6. 사용자가 사람 확인을 하면 `e2e_check apply`로 반영한다. 결과는 ADR 0028에 기록한다.
7. 실행이 멈추면 멈춘 곳과 이유를 기록한다. 같은 계약으로 남은 회차만 다시 돈다.

## 결과

- **예상 비용:** 약 $25. 개발용 -2 기준으로 세션 하나에 약 $0.29~0.30, 72세션이면 약 $21이다. 판정 입력이 생성 입력 전체로 늘어나는 몫을 더했다.
- **한계:** 엔진 안에서 법령 검색 후보에 정답 구간이 들어오지 않는 실패가 개발용에서 가장 많았다. 그래서 두 구성 모두 통과율이 낮을 수 있다. 판정은 두 구성의 비교로 한다.
