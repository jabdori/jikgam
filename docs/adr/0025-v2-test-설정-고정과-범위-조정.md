## 맥락

val로 값을 골랐다(`PROGRESS.md` 2026-10-16). 임베딩은 ADR 0024 보완의 지연 조건으로 다시 골랐다. test를 한 번 돌리기 전에, 무엇으로 쟀는지 나중에 확인할 수 있게 설정을 고정한다(ADR 0019와 같은 방식).

사용자가 2026-10-18에 순서를 바꿨다. 시연할 화면을 먼저 끝내고 test는 그 뒤에 한다. 그래서 test는 이 결정 기록을 담은 커밋(고정 커밋)의 깨끗한 사본에서 돈다. 화면 작업이 test 코드에 섞이지 않게 하려는 것이다.

## 결정: 범위 조정(사용자 결정, test 전)

1. **엔드투엔드는 다음 일로 남긴다.** 미공개 시나리오 12개 × 3회(§4.4)를 이번에 돌리지 않는다. §8.4는 판정하지 않는다.
   - 엔진의 법령·고시 묶음(`config/v2/law.toml`, `jikgam/engine/law.py`), 개발용 시나리오 12개, 미공개 시나리오(별도 작성자)는 저장소에 둔다.
   - 개발용 실행(`results/engine/scenarios/dev-v2-r0-1`, `dev-v2-r4-1`)에서는 정답 법령 구간을 후보로 찾고도 근거로 고르지 못한 경우가 많았다. 그래서 법령 구간 전용 판별 질문(`law_applies`)과 생성 규칙 20을 더했다. 이 고침은 개발용 시나리오로 다시 재지 않았다.
2. **답변 품질 판정은 1회만 한다.** §4.3의 3회 반복을 1회로 줄인다. 반복 사이 변동은 보고하지 못한다.
3. **독립 검토는 §8 판정 수치에 한정한다.** 측정과 분리된 검토자가 원본 로그에서 판정 수치를 다시 계산해 대조한다.

코디네이터가 정한 것도 하나 있다(사용자에게 보고). §3.6의 "보고만 하는 변형" 가운데 생성형 검색어 고쳐 쓰기와 참조 그래프는 구현하지 않아 이번 보고에서 빠진다. 나머지 변형((a)에 구간 정보, 구간 정보 없는 하이브리드, 고객 표현을 뺀 구간 정보, 다른 임베딩의 R4)은 보고한다.

## 결정: test 전에 정한 계산 정의(독립 리뷰 반영)

test 실행 코드를 `gpt-6-astra`가 리뷰해 11건을 지적했다(높음 4건). 고친 뒤 다시 확인해 4건을 더 찾았다(높음 2건). 기준 문서의 문장과 코드가 달랐거나, 문서가 정하지 않은 계산을 test 전에 정한 것이다.

- **근거 없는 주장 비율:** 판정 대상 질문(단일 근거 + 근거 없음)의 근거 없는 주장 수 합 ÷ 전체 주장 수 합이다. §4.3의 문장대로다.
  - 기존 코드는 질문별 비율의 평균을 냈고, 근거 없음 질문을 판정에서 뺐다. 주장 수가 다른 답이 섞이면 비교 방향이 바뀔 수 있어 문서 정의로 고쳤다.
  - 정답률과 보류율은 단일 근거 질문, 단정률은 근거 없음 질문으로 낸다.
  - 구간은 질문 단위로 짝지어 다시 뽑고, 표본마다 같은 정의로 다시 계산한다.
- **사람 확인 일치율(§4.3):** 근거 있음/없음 일치율이 근거 없는 주장 비율 조건을, 정답 판정 일치율이 정답률 조건을 가른다. 각각 0.80 미만이면 그 조건만 "판정 보류"다. 둘 다 맞은 비율도 보고한다.
- **덩어리 반복 분할(§4.1):** 두 가지를 보고한다.
  - 모델이 고른 경계만 비교한 일치(실행 사이)
  - 본 실행과 같은 Cmax 후처리를 거친 최종 경계의 일치(실행 사이, 각 실행 대 본 실행)
  - (c)의 확률은 본 실행처럼 소수 넷째 자리로 반올림한 뒤 θ와 비교한다.
  - (c)의 모델 입력 맥락은 본 실행(θ 0.5로 돈 실행)의 경계로 만들고, Cmax 후처리의 시작 상태는 고른 θ의 최종 경계에서 구한다.
- **재시도(§4.5):** Jev 리랭킹과 (c)의 경계 판단에도 2·4·8초 뒤 최대 3번 다시 보내기를 둔다. 모두 실패했을 때만 정해 둔 대체 처리를 한다.
  - 리랭킹 지연(§4.2, §8.2)은 성공한 Jev 호출 하나의 지연이다. 재시도와 대기를 넣은 전체 시간은 따로 보고한다. 모두 실패한 질문은 지연 계산에서 빼고 그 수를 적는다.
- **판정 계산의 자릿수:** 판정은 반올림하지 않은 값으로 하고, 반올림은 표시에만 쓴다.
- **사람 확인의 대상:** 사람 확인 결과는 그때의 답변 파일·단계 기록 해시와 표본 내용에 묶는다. 답변을 다시 만들면 이전 사람 확인은 쓰지 않는다.
- **보고 항목(§2.4·§4.1·§6):** 모든 검색 지표를 묶음별로 낸다. 두 질문 세트의 낱말 겹침 비율과, 구간 정보 비용(분할 비용과 따로)을 보고한다.
- **재개:** 단계마다 성공한 뒤에만 완료 표식을 쓴다(명령, HEAD, 고정 파일 해시, 산출물 해시). 표식이 맞을 때만 그 단계를 건너뛴다. 보고 단계는 늘 다시 계산한다.

## 결정: 작업 분담(2026-10-18 사용자 지시)

코디네이터(Claude)가 역할을 나누고 Orca로 Codex 작업자를 맡겼다. 모델은 Orca에서 쓸 수 있는 것을 확인한 뒤 공개 자료로 골랐다.

| 역할 | 모델 | 이유 |
|---|---|---|
| test 실행 코드, 화면 구현 | `gpt-6.1-sol`(high) | DeepSWE 75.2%로 `gpt-6-astra`(74.1%)와 같은 수준이고, 단가는 1/5이다 |
| test 실행 코드 리뷰 | `gpt-6-astra`(xhigh) | 판정 수치를 만드는 코드다. 어려운 추론 과제에서 Sol보다 앞선다(Terminal-Bench Science 11.1%p) |
| 화면 독립 리뷰(ADR 0022의 7) | `gpt-6-astra`(high) | 스크린샷을 봐야 한다. `zai/glm-5.3`은 이미지 입력이 없다 |
| test 뒤 독립 검토 | `zai/glm-5.3`(high) | 구현(OpenAI)과 코디네이터(Anthropic)와 계열이 다르다. 문맥이 100만 토큰이다 |

- 세 모델 모두 같은 작은 확인 작업(파일을 고치지 않고 명령 두 개를 실행)을 먼저 통과했다.
- 작업자는 커밋하지 않는다. 열람 규칙(test 질문, 참고 경계, 점검용 질문, 미공개 시나리오)은 작업 명세마다 적었다.

## 결정: 실행 절차

1. 고정 커밋으로 새 작업 사본(git worktree)을 만든다. 저장소 밖 자료(`data/v2/local/`)와 키 파일(`.env`)은 원래 작업 공간에서 복사한다. `jikgam.v2.freeze verify --adr 0025`가 해시를 확인한다.
   - 말뭉치 임베딩 캐시는 고정 전에 모든 구성의 것을 미리 만들어 해시에 넣었다(`freeze prepare`). 실행 중에 고정 입력이 늘거나 바뀌지 않게 하려는 것이다.
2. 덩어리 반복 분할에 쓰는 튜닝 2B 서버를 WSL2에서 띄운다. 실행 스크립트가 인증된 요청과 서버가 올린 가중치의 해시를 먼저 확인한다.
3. 테스트 실행 비용을 사용자에게 확인받은 뒤 `scripts/run_v2_test.sh`를 한 번 돌린다.
   - 실행이 멈추면 멈춘 곳과 이유를 진행 기록에 남긴다. 같은 설정으로 남은 단계만 다시 돈다(스크립트는 결과가 있는 단계를 건너뛴다).
4. 결과를 본 뒤에는 기준(`docs/evaluation-v2.md`)과 이 설정을 바꾸지 않는다.
5. 판정은 `jikgam.v2.report`의 값으로 한다.
   - 측정과 분리된 검토자가 원본 결과와 단계 기록에서 §8 판정 수치를 따로 계산해 대조한 뒤 기록한다.
   - 검토자는 Codex `zai/glm-5.3`이다. 구현(Codex `gpt-6.1-sol`)과 코디네이터(Claude)와 계열이 다르다.
6. §4.3의 사람 확인(무작위 30개 주장)은 그대로 한다.
