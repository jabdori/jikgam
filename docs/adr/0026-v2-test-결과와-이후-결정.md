## 맥락

ADR 0025로 설정을 고정한 커밋(`89eca24`)의 수정 없는 작업 사본에서, 2026-10-18에 `scripts/run_v2_test.sh`를 한 번 돌렸다.

- 단계 27개(test 검색 15, 점검용 검색 5, 답변 2, 덩어리 반복 분할 3, 사람 확인 화면 1, 보고 1)가 모두 첫 시도에 끝났다. 해시 확인(`freeze verify`)을 통과했고, 실행 뒤 작업 사본에 생긴 변경은 결과 폴더뿐이다.
- 시작할 때 Windows의 WSL 서비스가 꺼져 있어 튜닝 2B 서버 없이 시작했다. 서버가 필요 없는 단계부터 돌렸고, 그사이 서비스를 다시 켜서 같은 사본의 코드로 서버를 띄웠다. 서버가 돌려준 가중치 해시는 `3f9dcfe6df110822`로 고정값과 같았고, 인증 없는 요청은 401로 막혔다. 2B가 필요한 단계(덩어리 반복 분할 c-qwen) 전에 서버가 떠서 실행은 멈추지 않았다.
- 판별 호출의 최종 실패는 0건이다. Jev 리랭킹은 test 구성마다 174회, 점검용 구성마다 48회 호출했고 오류는 0건이다.
- 실제 비용은 약 $5.75다(예상 약 $8).

  | 항목 | 비용 |
  |---|---|
  | 답변 생성·판정 | $5.05 |

사람 확인(무작위 30개 주장)은 사용자가 판정 모델의 라벨을 보지 않고 했다. `claim_check apply`로 적용하고 보고를 다시 만들었다.

측정과 분리된 검토자(Codex `zai/glm-5.3`)가 판정 수치를 따로 계산해 대조했다.
- 기록: `results/v2/test-review/recompute.md`(§8 조건), `claims.md`(사람 확인)
- 계산 스크립트: 같은 폴더의 `recompute_t5.py`. 저장소 밖 단계 기록(`data/v2/local/runs/`)이 있어야 돈다.
- 결과 파일의 질문별 저장 값은 쓰지 않았다. 단계 기록의 구간 순서, 구간의 원문 위치, 정답 근거 위치에서 다시 계산했다.

- 사람 확인 일치율과 그에 따른 판정 보류 여부도 따로 계산해 같았다.
- p95를 가장 가까운 순위 방식으로 내도 판정은 같았다.

결과 파일:

## 결과(사전 기준 판정)

### §8.1 검색이 병목이 되는가: 정확도 병목이다

| 조건 | 값 | 기준 | 결과 |
|---|---|---|---|
| R0 근거 재현율@2,000(test 단일 근거 103) | 0.748 | 0.80 미만이면 병목 | 병목 |
| R0 검색 단계 p95 | 5.9ms | 250ms 넘으면 병목 | 병목 아님 |

같은 조건에서 R0-원형은 0.563, 검색 p95는 3.7ms다.

### §8.2 새 방식(R4)이 단순한 방식보다 나은가: "낫다"로 판정하지 않는다

조건 일곱 가운데 R4 리랭킹 p95 하나를 만족하지 못했다. 이 절은 모두 만족할 때만 "낫다"로 본다.

| 조건 | 값(95% 구간) | 기준 | 결과 |
|---|---|---|---|
| R4 − R0 재현율@2,000 | +20.4%p [+11.7, +29.1] | 10%p 이상, 아래 끝 > 0 | 만족 |
| R4 − R1 재현율@2,000 | +18.4%p [+9.7, +27.2] | 아래 끝 > 0 | 만족 |
| 점검용 R4 − R0(단일 근거 30) | +6.7%p [0, +16.7] | 점추정 > 0 | 만족 |
| R4 검색 단계 p95 | 83.4ms | 250ms 이하 | 만족 |
| R4 리랭킹 p95(성공한 Jev 호출) | 259.7ms | 250ms 이하 | **불만족** |
| 근거 없는 주장 비율 R4 − R0 | 0 − 0 = 0 | R4 ≤ R0 | 만족 |
| 정답률 R4 − R0 | 96.1% − 80.6% = +15.5%p [+7.8, +23.3] | R4 ≥ R0 | 만족 |

- 재현율은 R0 0.748, R1 0.767, R4 0.952다.
- 리랭킹 p95를 재시도 포함 시간으로 내면 259.8ms, 가장 가까운 순위 방식으로 내면 269.1ms다. 같은 Jev로 v1 test에서 잰 p95는 233ms였다(ADR 0015). v2에서 더 느린 원인은 따로 재지 않았다. 다만 v2 R4의 후보 구간은 평균 514토큰으로 길다.
- 점검용 R4 리랭킹 p95는 253.6ms다(보고).
- **근거 없는 주장:** 판정 모델이 R0 135개, R4 170개 주장을 모두 '근거 있음'으로 판정했다. 판정 오류는 0건이다. 그래서 이 조건은 두 방식을 가르지 못한다(바닥 효과).
- **사람 확인:** 무작위 30개 주장(R4 21개, R0 9개)에서 근거 판정 30개, 정답 판정 30개가 판정 모델과 같았다. 두 일치율 모두 1.00으로 기준 0.80 이상이라, 답변 품질 두 조건은 판정 보류 없이 판정한다.
  - 표본 30개에서도 근거 없는 주장은 없었다. 다만 30개로 말할 수 있는 것은, 0건일 때 근거 없는 주장 비율의 95% 상한이 약 10%(3/n 규칙)라는 정도다.

### §8.3 경계 판단을 판별 모델로 바꿔도 되는가: 둘 다 아니다

| 구성 | 재현율@2,000 − R4 | 분할 비용 | 분할 시간 | 결과 |

| R4c-Jev | −3.9%p [−8.7, 0] (기준 −3%p 이상) **불만족** | $0.0266 ≤ $0.0528 만족 | 8.1초 ≤ 60.9초 만족 | 바꾸지 않는다 |

### §8.4 엔드투엔드: 판정하지 않았다(ADR 0025)

v2 규모에서 근거 갱신 시간을 재지 않았다. 리랭킹 p95가 250ms를 넘은 것이 근거 갱신 목표(500ms)에 어떤 영향을 주는지도 아직 모른다.

## 결정

1. 판정은 위 표대로 기록한다. 기준(`docs/evaluation-v2.md`)과 고정 설정(ADR 0025)은 바꾸지 않는다. test는 다시 쓰지 않는다.
2. **검색 방식:** v2 검색은 R4 구성(문맥 분할 (b), 구간 정보, snow 하이브리드, Jev 리랭킹 8)을 그대로 쓴다.
   - 재현율은 R0보다 크게 나아졌다.
   - 다만 리랭킹 지연 조건을 넘었으므로 "단순한 방식보다 낫다"고 쓰지 않는다. 재현율 개선과 리랭킹 지연 미달을 함께 적는다.
3. **경계 판단:** 경계 판단은 (b) gemini-3.8-flash로 둔다. (c-Jev)는 재현율에서, (c-Qwen)은 시간에서 기준을 넘지 못했다.
4. **리랭킹 지연:** 다음 엔드투엔드에서 v2 규모의 근거 갱신 시간을 잴 때 함께 본다. 지연을 줄이는 변경(후보 수, 구간 길이)을 시험하려면 새 기준을 먼저 문서로 정하고 test가 아닌 자료로 고른다.
5. **답변 품질 판정:** 두 조건은 사람 확인 일치율 1.00으로 그대로 판정한다. 근거 없는 주장 비율은 두 방식 모두 0이라 이번 자료로는 차이를 가르지 못했다. 다음에 답변 품질을 잴 때(엔드투엔드) 이 바닥 효과를 기준을 정하는 단계에서 먼저 다룬다.

## 한계

- 질문과 정답은 AI가 만들었다. 사람 검토에서 단일 근거 질문의 문제 비율은 24%였다(§8 보완).
- 답변은 1회만 만들어 반복 사이 변동을 보고하지 못한다.
- 근거 없는 주장 0건은 판정 모델 한 개(gemini-3.1-pro-preview)의 판정이다.
- 지연은 이 PC에서 잰 값이다. Jev는 네트워크 호출이다.
