# 독립 리뷰: 관리 콘솔 · 고객사 관리

> 처음 읽는다면: [디자인 하네스](../README.md) · [ADR 0022](../../adr/0022-디자인-하네스.md)

- 리뷰어: 구현을 보지 않은 별도 에이전트(스크린샷과 시안만 봄)
- 본 것: `screens/admin-tenants-1440.png`, `screens/admin-tenants-390.png`, 시안 `mock/Tenants.dc.html`, 비교용 다른 화면
- 1차 리뷰: 2026-10-15

## 지적(원문 요약)

1. [높음] [5] 설정 차이표 — 표 위에 `config/orgs/*.toml` 하나만 있고 행마다 어느 설정 키에서 온 값인지 안 보인다. 구어 확장 규칙, 질문 세트, 어댑터는 toml에 있는 값인지도 모른다. — 항목 아래에 설정 키와 출처 파일을 적고 열 제목에 org 이름도 적는다.
2. [높음] [390] 설정 차이표 — "책솔" 열이 보이지 않고 값이 잘린다. — 좁은 폭에서는 행마다 두 고객사 값을 세로로 쌓는다.
3. [중간] [1][4][5] 온보딩 "상담 기록(재생·시나리오 실행)" — 실행을 했다는 뜻일 뿐 사전 기준 통과는 보이지 않고, 이름도 요구 사항의 "벤치마크"와 다르다. — "벤치마크 실행"으로 바꾸고 결과로 연결한다.
4. [중간] [1] "파일 3개 · 목표는 없음" — "목표가 없다"로 읽힌다. 목표를 못 이뤘다는 신호도 사라졌다. — "변경 2건 · 파일 3개 · 목표 0건"으로 쓰고 경고색을 쓴다.
5. [중간] [2] "(a) 일반화" 두 항목 — 같은 변경이 파일 수만큼 두 번 나온다. — 변경 하나에 블록 하나, 그 아래 파일을 나열한다.
6. [중간] [1] 엔진 코드 카드 — 시안의 "별담 플러스 동작은 바꾸지 않음"이 빠졌다. — 기존 고객사 영향과 확인 근거를 붙인다.
7. [중간] [4] 1440 고객사 목록 — 시안과 390에서는 위에 있는데 1440에서는 오른쪽 열이고 그 아래가 비어 차이표가 좁아진다. — 위쪽 가로 카드로 두고 차이표를 전체 폭으로.
8. [중간] [2] 차이표의 "질문 세트", "업무 API 어댑터" — 온보딩 값과 겹친다. — 차이표에서 뺀다.
9. [낮음] [4] 차이표 열 폭 — 항목 열이 좁아 두 줄로 꺾이고 고객사 열 폭이 다르다.
10. [낮음] [2][4] "운영 준비됨" 배지 — 두 고객사가 같아 구분되지 않고 기준이 안 보이며 시안의 "운영 중/온보딩"과 다르다. — 온보딩일 때만 남은 항목 수를 보인다.
11. [낮음] [5] 체크리스트 근거 줄 — 전체 경로, 파일 이름만, 실행 ID, 문장이 섞여 있다. — 하나로 통일한다.
12. [낮음] [2][1] "필수 안내"의 개수와 "구어 확장 규칙"의 개수 — 개수가 목록과 겹치거나 무엇이 다른지 알 수 없다.
13. [낮음] [4] 식별자 글꼴 — `family_addon`, `duplicate_window_days`가 본문 글꼴이다. — mono로 맞춘다.
14. [낮음] [4] 오른쪽 열 — 시작 높이가 모델·벤치마크 화면과 다르다.
15. [낮음] [390] 카드 여백 두 겹, 맨 위 "내부용" 안내 상자가 세로 공간을 차지한다.

전체 평가(원문 요약): 사이드바·카드·표 스타일은 다른 관리 화면과 맞고 엔진 코드 변경도 파일 단위로 추적된다. 그러나 "설정만으로 붙였는가, 아니라면 기존 고객사 영향이 없는가"와 "차이마다 근거가 어느 키·파일인가"를 바로 판단할 수 없다. 390에서 책솔 열이 안 보이는 것부터 고친다.

## 처리

| 지적 | 처리 |
|---|---|
| 1 | 반영. 항목 이름 아래에 설정 키(`policy.window_days` 등)를 적고, 표 머리에 출처 `config/orgs/<org>.toml`, 열 제목에 조직 이름과 ID를 함께 적었다. |
| 2 | 반영. 좁은 화면에서 행마다 두 고객사 값을 세로로 쌓는다. |
| 3 | 반영. 이름을 "벤치마크 실행(상담 재생·시나리오)"로 바꾸고 실행 폴더 경로를 적었다. 조직 B에는 사전 기준을 정한 평가가 없어 통과 배지는 두지 않는다. |
| 4 | 반영. "변경 2건 · 파일 3개 · 목표는 변경 없음"을 경고색으로 적었다. |
| 5 | 반영. 같은 분류의 행을 한 변경으로 묶고 그 아래 파일을 나열한다. "(a)" 같은 기호는 뺐다. |
| 6 | 반영. 기록 문서에 기존 고객사 동작을 바꾸지 않았다는 근거가 있으면 "기존 고객사 동작: 바꾸지 않음(근거 docs/org-b.md §5)"을, 없으면 경고를 보인다. |
| 7 | 반영. 고객사 목록을 위쪽 가로 카드로 옮기고 차이표를 전체 폭으로 넓혔다. |
| 8 | 반영. 질문 세트와 어댑터 행을 차이표에서 뺐다(온보딩에만 둔다). |
| 9 | 반영. 항목 열을 고정 폭으로 두고 표를 고정 배치로 바꿔 고객사 열 폭이 같다. |
| 10 | 반영. 다 갖춘 고객사는 배지를 달지 않고, 온보딩 중일 때만 "온보딩 · 남은 항목 n개"를 보인다. |
| 11 | 반영. 근거 줄을 모두 저장소 경로(또는 환경 변수 이름) 고정폭 글자로 통일했다. |
| 12 | 반영. 필수 안내는 개수를 빼고 목록만, 구어 확장 규칙은 "규칙 수"로 이름을 바꾸고 설정 키를 적었다. |
| 13 | 일부 반영. 설정 값의 식별자(`family_addon`)는 고정폭이다. 엔진 변경 설명은 기록 문서의 글을 그대로 옮긴다. |
| 14 | 반영. 7번으로 오른쪽 열이 없어졌다. |
| 15 | 반영. 좁은 화면에서 관리 콘솔 안내 상자를 숨기고 표 카드 여백을 하나로 맞췄다. |
