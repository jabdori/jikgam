> 처음 읽는다면: [디자인 하네스](../README.md) · [ADR 0022](../../adr/0022-디자인-하네스.md)

- 본 것: `screens/admin-replay-1440.png`, `admin-replay-390.png`, `admin-replay-barge-1440.png`, `admin-replay-barge-390.png`, 시안 `mock/Trace.dc.html`, 비교용 다른 화면
- 1차 리뷰: 2026-10-15

## 지적(원문 요약)

1. [높음] [5] 재생 목록의 판단 행(1440) — 왼쪽 열이 약 258px라 판단 요약이 8~10자에서 잘려 v1~v4가 같아 보이고, 어느 판단에서 이전 답이 무효가 됐는지 목록만으로 알 수 없다. — 열을 넓히거나 판단 행을 두 줄로, 또는 무효 표식을 앞에 둔다.
2. [높음] [5][390] 통화 전체 순위 변화(390) — v1~v3 열만 보이고 현재 판단 열과 정답 일치 흐름이 화면 밖이다. — 현재 판단 열로 자동 스크롤하고 조항 열을 고정하거나, 현재 앞뒤 열만 보인다.
3. [중간] [390] 판단 상세의 위치 — 상세가 재생 목록 20여 행 아래에 있어 이전/다음 버튼과 떨어져 있다. — 상세를 플레이어 바로 아래에 둔다.
4. [중간] [2][4] 브라우저 기본 오디오 컨트롤 — 어두운 콘솔에서 가장 밝고, 진행 막대와 시각이 자체 타임라인과 겹친다. — 기본 컨트롤을 숨기고 재생 버튼과 자체 타임라인 하나만 둔다.
5. [중간] [5] 이전 확률 — 흐린 막대로만 나오고 숫자가 없어 변화량을 읽기 어렵다. — 직전 값을 작은 숫자로 붙인다.
6. [중간] [2] 조항 순위 카드 맨 아래 줄 — 선택·정답·일치 수가 모두 다른 곳에도 있다. — 뺀다.
7. [중간] [2][390] 통화 선택 상자와 상단 경로 — 실행 ID가 두 번씩 들어가고 경로에도 반복되며 390에서 "정책 C"가 잘린다. — 표시 이름을 줄인다.
8. [중간] [5][390] 타임라인의 현재 판단 표식 — 재생 위치 선이 표식 가운데를 지나 글자가 가려지고, 390에서 표식끼리 겹친다.
9. [낮음] [5] 순위 변화 표의 현재 열 — 제목만 굵어 눈에 잘 띄지 않는다. — 열 전체에 옅은 배경을 깐다.
10. [낮음] [1][2] 무효 사유 문단 — "suggestion_valid=false"는 무효라는 사실을 되풀이하고 요청 변경은 머리 배지·표와 겹친다. — 사유 코드 한 줄로 줄인다.
11. [낮음] [3][4] "재생 목록" 제목 — 화면에서 가장 큰 글자이고 설명이 붙은 유일한 제목이다. — 카드 제목 크기로 줄인다.
12. [낮음] [4] 오른쪽 끝 정렬 — 플레이어 카드와 아래 카드가 약 28px 어긋난다.
13. [낮음] [4] 체크박스 위 파란 "재생" 라벨 — 링크처럼 보이고 시안에 없다. — 빼고 체크박스를 이전/다음과 같은 줄에 둔다.
14. [낮음] [4] 용어 — 시안의 "의도 변경", "신규", "무효화 사유"가 "요청 변경", "새로", "무효 사유"로 바뀌었다. "새로"는 어색하니 "신규"를 권한다.
15. [낮음] [5] 순위 변화 표의 행 범위 — 어떤 조항이 행으로 뽑히는지와 "·"의 뜻이 범례에 없다.
16. [낮음] [390] 상단 영역 — 경로가 3줄로 꺾이고 안내 상자가 위에 있어 플레이어가 밀리며, 재생 목록 행이 낮다.

전체 평가(원문 요약): 요구한 정보(▲▼, 무효·새 답과 사유, 조항×버전 표, 정답 일치, 이전/다음, 판단마다 멈춤)가 모두 있고, 두 통화 모두 순위 카드와 표, 답 시각과 재생 목록 시각이 서로 맞는다. 1440 재생 목록 요약이 잘리고 이전 확률이 숫자로 보이지 않아 변화 추적이 상세 카드에만 기대며, 390에서는 순위 표와 상세 위치 때문에 핵심 작업이 어렵다.

## 처리

| 지적 | 처리 |
|---|---|
| 1 | 반영. 재생 목록 열을 넓히고(320~380px), 줄을 두 줄까지 보이며, 판단 줄은 "이전 답 무효"를 맨 앞에 둔다. |
| 2 | 반영. 순위 표의 조항 열을 고정하고, 열 때 현재 판단 열이 보이도록 가로 위치를 맞춘다(JS가 scrollLeft만 바꾼다). |
| 3 | 반영. 좁은 화면에서는 판단 상세를 재생 목록 앞에 둔다. |
| 4 | 반영. 기본 오디오 컨트롤을 숨기고 재생 버튼 하나와 재생 띠만 둔다(`player(native=False)`). 고객사 콘솔의 다시 듣기는 기본 컨트롤을 그대로 쓴다. |
| 5 | 반영. 확률 옆에 직전 확률을 "0.62 ← 0.67"처럼 숫자로 붙였다. |
| 6 | 반영. 카드 아래 줄을 뺐다. 정답 일치는 순위 표의 현재 열에서 읽는다. |
| 7 | 반영. 표시 이름을 "실행 · 시나리오 · 회차 · 정책"으로 줄였다. |
| 8 | 반영. 판단 표식을 재생 위치 선보다 위에 그린다. |
| 9 | 반영. 순위 표의 현재 열 칸마다 테두리를 둔다. |
| 10 | 반영. 무효 사유를 고정폭 코드 한 줄로 줄였다. |
| 11 | 반영. "재생 목록" 제목을 카드 제목 크기로 줄이고 설명을 뺐다. |
| 12 | 반영. 본문 안의 세로 영역 여백을 고쳐 오른쪽 끝을 맞췄다. |
| 13 | 반영. 묶음 이름 "재생"을 빼고 체크 상자를 이전/다음 판단과 같은 줄에 두었다. |
| 14 | 일부 반영. "새로"를 "신규"로 바꿨다. "요청 변경", "무효 사유"는 고객사 콘솔과 같은 말이라 유지한다(시안의 "의도 변경"은 내부 코드 intent를 옮긴 말). |
| 15 | 반영. 범례에 행 선정 기준과 "· = 후보 아님"을 적었다. |
| 16 | 반영. 좁은 화면에서 경로는 마지막 항목만, 관리 콘솔 안내 상자는 숨기고, 재생 목록 줄 높이를 44px로 했다. |

## 2차 확인(2026-10-15)

처리 뒤 새 스크린샷으로 다른 에이전트가 다시 확인했다(구현은 보지 않음). 1차에서 "반영"이라 적은 높음·중간 지적만 확인했다. 아래는 고쳐지지 않았거나 일부만 고쳐진 것, 새로 찾은 것과 그 처리다. 나머지는 고쳐진 것으로 확인됐다.

| 확인 결과 | 처리 |
|---|---|
| [중간] 7 일부 — 상단 경로에 통화 이름이 다시 나온다 | 반영. 경로에는 "통화 리플레이 / 시나리오 제목"만 둔다(통화는 선택 상자에 있다). |
| [중간] 8 일부 — 390에서 "v3–5" 표식이 "v6" 표식에 가린다 | 반영. 좁은 화면에서는 현재 판단만 글자로, 나머지 판단은 점으로 그린다(링크와 글자는 그대로 있어 화면 읽기 프로그램은 읽는다). |
| [낮음] 10 — 무효 사유가 세 줄이고 suggestion_valid=false가 남아 있다 | 반영. 다른 사유가 있으면 "suggestion_valid=false"는 뺀다. |
