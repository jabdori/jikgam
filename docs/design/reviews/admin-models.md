## 지적(원문 요약)

1. [높음] [4][1] 벤치마크 세트 카드 — 세트 이름은 작은 라벨인데 자료 설명이 페이지에서 가장 큰 글자로 2~4줄을 차지한다(위계가 뒤집힘). — 시안 위계로 되돌리고 높이를 줄인다.
2. [높음] [5] q35-2b-ko-direct의 p95 165ms — 다른 행은 번갈아 호출한 실행의 값인데 이 행만 혼자 돈 실행 값이라 가장 빠른 모델로 읽힌다. — 연속·간헐 값을 함께 적고 판정이 혼자 서빙한 p95로 한다는 표시를 둔다.
3. [높음] [5] 상담 방식 결과의 "일부 미달" — 어느 항목이 무슨 기준에 못 미쳤는지 없다. — 미달 항목을 적고 기준 문구를 둔다.
4. [높음] [390] 두 결과표 — 수치 열이 화면 밖으로 잘리고 스크롤 단서가 없다. — 좁은 폭에서는 행을 카드로 바꾼다.
5. [중간] [5][4] 상담 방식 결과 — 실행 ID, 반복 수가 없고 리플레이와 이름 체계가 달라 맞춰 볼 수 없다. — 실행 ID와 반복 수, 정책 문자를 적는다.
6. [중간] [5][4] 판별 표의 모델 이름 — 고정한 버전 ID가 없다(리플레이는 jev-1.13.0으로 보임). — 이름 아래 버전 ID를 적는다.
7. [중간] [5][1] 화면 실행 결과의 위치 — 결과표에 test와 미공개 결과가 섞여 있고, 화면에서 돌린 val 결과와 실행 중 상태가 어디에 나오는지 보이지 않는다. — 분할 열을 두고 실행 중인 모델을 표에 올린다.
8. [중간] [2][1] 세트 카드와 실행 체크박스 — 같은 네 이름이 두 번 나온다. — 설명을 체크박스 옆으로 옮기고 카드 줄을 없앤다.
9. [중간] [5] "간헐 호출 p95 457.2ms" — 회차표 어느 값과도 같지 않고 어느 회차를 묶었는지 없다. 4·5회차는 gemini-flash 없이 돌아 조건이 다르다. — 대상 회차와 범위를 적고 4·5회차를 나눈다.
10. [중간] [5] "미갱신 1"과 이전 답 노출 분모 — 무엇을 센 것인지 설명이 없다. — 열 머리에 단위, 미갱신은 각주로 설명한다.
11. [중간] [5] 로컬 모델의 1회 비용 "$0" — 자체 GPU 비용을 재지 않았을 뿐인데 0원으로 읽힌다. — "— (자체 GPU, 호출 과금 없음)"으로 쓴다.
12. [중간] [1] 모델 추가 폼 — 로컬 서버인데도 키·단가 칸이 보여 칸이 7개다. — 어댑터별로 필요한 칸만 보인다.
13. [중간] [390] 화면 순서 — 폼이 제목보다 먼저 나와 결과표가 2,000px 넘게 아래에 있다. — 제목 → 결과 → 폼 순서로 바꾼다.
14. [낮음] [2] 같은 실행 ID가 행마다 반복되고 q35 p95가 표와 타일에 두 번 나온다. — 공통 실행 ID는 표 머리로 올린다.
15. [낮음] [2] 상담 방식 표의 "자료" 열과 "판정 대상 아님" 반복 — 두 묶음으로 나누고 이유를 한 번만 적는다.
16. [낮음] [4] "생성형(Gemini)"이 정해 둔 어댑터 이름과 다르고, 실행 패널의 "clef"가 표의 "clef-flash"와 같은지 모른다.
17. [낮음] [5][4] clef-flash 판정 — 사유가 빨간 배지와 일반 글자로 다르게 표시되고 못 미친 수치 칸에 표시가 없다. — 한 형식으로, 못 미친 칸에 색을 준다.
18. [낮음] [5] "평가 기준 문서" — 경로가 없다.
19. [낮음] [기타] 1회 비용 자릿수가 제각각이다. — 한 단위로 맞춘다.
20. [낮음] [2][3] 모델 추가 폼 아래 설명 상자가 부제와 겹친다.
21. [낮음] [4] 오른쪽 열 시작 높이가 고객사 관리 화면과 다르다.
22. [낮음] [390][1] 부하 빈 상태 문구 "오른쪽에서…"가 390에서는 틀린 안내다.

전체 평가(원문 요약): 정보 구성은 시안을 따르고 판별 표는 출처가 가장 잘 추적된다. 세트 카드의 위계 역전, p95 열에 조건이 다른 값이 섞인 것, 상담 방식 표에 출처와 판정 근거가 빠진 것이 문제이고, 390에서는 두 결과표의 수치가 잘린다.

## 처리

| 지적 | 처리 |
|---|---|
| 1 | 반영. 세트 카드를 없애고 세트 이름과 설명을 벤치마크 실행 폼의 선택지로 옮겼다(8번과 같이). |
| 2 | 반영. 로컬 모델의 p95 칸에 "혼자 서빙"을 붙이고 아래에 간헐 호출 p95를 함께 적었다. 사전 기준 문구에도 "혼자 서빙한 p95"로 판정한다고 적는다. |
| 3 | 반영. 못 미친 조건을 배지로 적는다("미달: 근거 갱신"). 기준 문서(`docs/evaluation-voice.md §5(ADR 0017)`)를 표 아래에 적었다. |
| 4 | 반영. 결과표를 모두 좁은 화면에서 카드로 쌓는다. |
| 5 | 반영. 방식 이름 아래에 정책 문자와 실행 폴더를 적고, 채팅·개발용과 음성·미공개를 나눠 세션 수를 묶음 제목 옆에 둔다. 리플레이로 가는 링크는 미공개 시나리오 세션이 잠겨 있어 두지 않았다. |
| 6 | 반영. 모델 이름 아래에 설정의 모델 ID(버전)를 적었다. |
| 7 | 반영. "분할" 열(test/val)을 두었다. 화면에서 시작한 실행은 맨 위 "이 서버에서 시작한 벤치마크"에 상태와 함께 보이고, 끝나면 결과가 val 행으로 들어온다. |
| 8 | 반영. 1번과 같다. |
| 9 | 반영. 간헐 호출은 생성형 기준선과 번갈아 돈 회차(1·2·3회차)의 p95 범위로 보이고, 실행 전체 p95와 회차 목록을 함께 적었다. 회차표에 "조건" 열을 두어 판별 API와만 번갈아 돈 회차(4·5회차)를 나눴다. 열 이름은 "회차 p95". |
| 10 | 반영. 열 머리에 단위를 적고("상담 통과(유효 실행)", "근거 갱신 p95(조건 변경)", "이전 답 노출(노출/대상)") 미갱신과 대상의 뜻을 표 아래에 적었다. |
| 11 | 반영. 로컬 모델은 "자체 GPU"로 적고 기준 문구에 호출 과금이 없어 비용을 적지 않는다고 적었다. |
| 12 | 반영. 어댑터가 로컬 서버면 키·단가 칸을 숨긴다(`field_text(show_for=…)`, JS가 hidden 속성만 바꾼다). |
| 13 | 반영. 좁은 화면에서는 제목과 결과가 먼저, 폼이 뒤에 온다(`split(aside_first=False)`). |
| 14 | 반영. 공통 실행 ID와 판단 수를 표 머리로 올리고, 행에는 다른 실행일 때만 적는다. |
| 15 | 반영. 5번처럼 묶음으로 나누고, 판정 대상이 아닌 칸은 "—"로 두고 이유를 표 아래에 한 번만 적었다. |
| 16 | 반영. Gemini 백엔드는 "생성형 기준선(Gemini API)"으로 적는다(등록하는 세 어댑터와 구분되는 기존 기준선). 실행 폼의 선택지는 "이름 · 모델 ID"로 보여 clef와 clef-flash가 다른 모델임이 보인다. |
| 17 | 반영. 못 미친 조건은 같은 모양의 빨간 배지로 나란히 두고, 못 미친 수치 칸(정확도·p95·비용)을 빨간 글자로 표시한다. |
| 18 | 반영. 기준 문서 경로(`docs/evaluation.md §7.1·§7.2`)를 적었다. |
| 19 | 반영. 1회 비용을 소수 여섯째 자리로 맞췄다. |
| 20 | 반영. 설명 상자를 빼고 문구를 부제에 합쳤다. |
| 21 | 유지. 고객사 관리 화면을 오른쪽 열 없는 배치로 바꿔(그 화면 지적 7) 비교할 오른쪽 열이 없다. |
| 22 | 반영. "벤치마크 실행에서 부하를 고르면 여기에 보입니다." 한 줄로 줄였다. |

## 2차 확인(2026-10-15)

처리 뒤 새 스크린샷으로 다른 에이전트가 다시 확인했다(구현은 보지 않음). 1차에서 "반영"이라 적은 높음·중간 지적만 확인했다. 아래는 고쳐지지 않았거나 일부만 고쳐진 것, 새로 찾은 것과 그 처리다. 나머지는 고쳐진 것으로 확인됐다.

| 확인 결과 | 처리 |
|---|---|
| [높음] 3 일부 — "미달: 근거 갱신"만 있고 무슨 기준에 못 미쳤는지 수치가 없다 | 반영. 배지 아래에 음성 보고서의 판정 문구와 값을 그대로 적는다(예: "근거 갱신: C p95 500ms 이하, A p95의 1/10 이하 — C 1,231ms, A 18,635ms, 비 0.066"). |
| [중간] 5 일부 — 반복 수가 없다 | 반영. 묶음 제목 옆에 "시나리오마다 3회"를 적는다(채팅은 실행 폴더 수, 음성은 보고서의 회차 수). |
| [중간] 7 일부 — 화면에서 시작한 실행이 어디에 나오는지 알 수 없다 | 반영. 판별 표 아래에 "화면에서 시작한 실행은 맨 위 표에 상태가 보이고, 끝나면 val 행으로 들어온다"를 적었다. |
| [중간] 9 일부 — 판별 표의 "간헐 457ms"가 어느 회차인지 모른다 | 반영. "간헐(실행 전체)"로 적어 튜닝 모델 지연 카드의 회차별 값과 구분한다. |
| [낮음] 새 문제 — 음성 묶음의 개선형 RAG 판정 칸이 "—"인데 이유가 없다 | 반영. 판정한 묶음 안에서 판정이 없는 행은 "비교 기준"으로 적는다. |
| [낮음] 새 문제 — 실행 폴더 이름과 체크 상자 이름이 중간에서 꺾인다 | 유지. 좁은 열에서 줄바꿈이 생긴다. 내용은 그대로 읽힌다. |
