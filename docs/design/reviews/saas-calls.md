## 지적(원문 요약)

목록 + 상세

1. [높음] [390] 통화 목록 표 — 고객과 문의 일부만 보이고 처리 결과·금액·시간·일시가 가로 스크롤 밖에 있다. — 좁은 폭에서는 행마다 카드로 바꾸고 처리 결과를 첫 화면에 보인다.
2. [높음] [390] 상세 드로어 — 목록 12행과 쪽 넘김 아래에 붙어, 행을 눌러도 화면이 바뀌지 않는 것처럼 보인다. — 전체 화면 시트나 별도 화면으로 띄운다.
3. [중간] [2] 요약 — 요청 흐름과 "해지 접수"가 문의 열·배지·처리 내역과 세 번씩 겹치고, 시안 요약에 있던 환불 불가와 그 이유가 빠졌다. — 다른 곳에 없는 내용만 남긴다.
4. [중간] [4] 처리 결과 색 — 목록 배지와 운영 리포트 막대가 같은 분류를 다른 색으로 쓴다. — 한쪽에 맞춘다.
5. [중간] [4] 요청을 바꾼 횟수 — 문의 열은 두 번 바뀌었는데 상세와 대화의 구분선은 첫 번째만 보인다. — 두 번째 변경도 표시하거나 문의 열을 맞춘다.
6. [중간] [기타] 같은 고객의 통화 구분 — 송하은 고객의 두 행이 문의·결과·상담 시간까지 같은데 상세 머리말에 시각이 없다. — 시각을 넣는다. 실제로 중복 기록이면 진행 기록에 남긴다.
7. [중간] [기타] 줄바꿈 — 단어와 번호 중간에서 줄이 끊긴다. — 어절 단위로 바꾸고 전화번호는 한 줄에 둔다.
8. [낮음] [1] "잘못된 안내는 나가지 않았습니다." — 28건 모두 같은 문장이 붙어 할 일이 없다. — 실제로 나갔을 때만 경고로 보인다.
9. [낮음] [1][4] "기록 조회 4건" — 무엇을 조회했는지 모르고 "기록"이 화면 이름과 겹친다. — "구독·결제 내역 조회"로 쓰고 건수를 뺀다.
10. [낮음] [4] 처리 내역의 빈 원 — 여기서는 "대상 아님", 실시간 통화에서는 "아직 안 함"이다. — 모양을 구분한다.
11. [낮음] [4] 필터 칩과 결과 배지 이름 — 칩은 다섯 분류인데 배지는 더 잘게 나뉜다. — 배지를 칩 분류에 맞춘다.
12. [낮음] [4] "요청 바뀜 28" 칩 — 처리 결과 칩과 같은 줄·같은 모양이라 여섯 번째 결과처럼 보인다. — 따로 떼고 이름을 리포트와 맞춘다.
13. [낮음] [2] 건수 94 — 부제, "전체" 칩, 쪽 넘김에 세 번 나온다. — 부제에서 뺀다.
14. [낮음] [4] 기간 표시 — "7일"을 골랐는데 부제는 이틀 범위다. — 고른 범위를 그대로 보인다.
15. [낮음] [1] "고객 6턴" — "턴"은 운영팀 말이 아니다. — 뺀다.
16. [낮음] [4] 안내 근거 칩 — 파란 글자라 링크처럼 보인다. — 누르면 원문이 열리면 그대로 둔다.
17. [낮음] [2] "대화 전체 보기"와 "녹음 듣기" — 같은 화면으로 가는 것처럼 보인다. — 하나로 합친다.
18. [낮음] [4] 본문 여백(1440) — 목록 화면만 왼쪽 24px이다. — 28px로 맞춘다.
19. [낮음] [390] 본문 여백 — 목록 화면 본문만 32px이다. — 16px로 맞춘다.
20. [낮음] [390] 상단 메뉴 — 잘리고 넘침 표시가 없다.
21. [낮음] [390] 필터 칩 — 세 줄로 접혀 약 120px을 차지한다. — 한 줄 가로 스크롤로 바꾼다.

대화 전체

1. [중간] [1] 안내 근거 — 조항이 대화 줄과 연결되지 않아 어느 안내의 근거인지 모른다. — AI 줄 옆에 그 줄의 근거 조항을 붙인다.
2. [중간] [기타] 개인정보 — 목록은 번호를 가리는데 대화에는 전체 번호와 인증번호가 그대로 나온다. — 가림 규칙을 같게 한다.
3. [중간] [기타] 줄바꿈 — 단어 중간에서 끊긴다.
4. [중간] [390] 순서 — 요약·처리 내역·근거가 대화 아래 약 1,900px 지점에 있다. — 요약을 머리말 아래에 둔다.
5. [낮음] [390] 대화 줄 배치 — 화자 이름이 한 줄을 차지하고 시간 열이 본문 폭을 줄인다. — 시간을 화자 줄로 올린다.
6. [낮음] [2] 통화 길이 — 머리말 "2분 20초", 재생기 "2:21". — 같은 값으로 맞추거나 머리말 쪽을 뺀다.
7. [낮음] [2] 해지 접수가 배지·요약·처리 내역에 세 번 나온다.
8. [낮음] [3] "대화" 제목 옆 설명 — 재생하면 드러나는 내용이고 설명이 붙은 제목은 이것뿐이다. — 뺀다.
9. [낮음] [4] 처리 결과 배지 — 이름에서 멀리 오른쪽 끝에 있고 드로어 머리말에는 없다. — 이름 옆에 두고 드로어에도 넣는다.

전체 평가(원문 요약): 1440의 두 화면은 다른 화면과 같은 틀을 쓰고 장식·엔진 수치가 없다. 가장 큰 문제는 390 목록(처리 결과가 안 보이고 상세가 목록 끝에 붙음)이고, 그다음은 같은 사실의 반복과 처리 결과 색의 불일치다.

## 처리

| 지적 | 처리 |
|---|---|
| 목록 1 | 반영. 표 컴포넌트에 좁은 화면 카드 모양(`table(stack=True)`)을 더했다. 칸 이름이 값 앞에 붙고 처리 결과가 첫 화면에 보인다. |
| 목록 2 | 반영. 좁은 화면에서는 드로어를 목록 앞에 둔다(`.col-drawer` 순서). 상세를 열면 포커스도 상세 제목으로 간다. |
| 목록 3 | 반영. 요약은 다른 곳에 없는 것만 적는다: 환불 접수액과 승인 대기, 환불 대상 아님과 근거 조항, 이용 마지막 날, 상담사 연결·보류·중간 종료 사유. 적을 것이 없으면 요약을 뺀다. |
| 목록 4 | 반영. 처리 결과 색을 한 표(`saas/common.py` OUTCOME_TONE)로 정해 배지와 리포트 막대가 같이 쓴다. |
| 목록 5 | 유지. 문의 열은 판별한 요청을 처음 나온 순서로 잇고, 구분선은 시나리오가 조건 변경으로 표시한 발화에만 둔다(`docs/design/data.md`). 두 번째 변화는 엔진이 판단한 요청의 변화이고 시나리오의 조건 변경이 아니다. 정의가 다르다는 것을 data.md에 적었다. |
| 목록 6 | 반영. 머리말에 시각(09:43)을 넣었다. 두 행은 같은 개발용 재생(s20)을 다른 회차로 돌린 서로 다른 통화다. 중복 기록이 아니다. |
| 목록 7 | 반영. 본문 전체에 `word-break: keep-all`. 전화번호는 고객 이름 아래 따로 둔다. |
| 목록 8 | 반영. 잘못된 안내가 나갔을 때만 빨간 경고로 보인다. |
| 목록 9 | 반영. "구독·결제 조회 · 완료"로 바꾸고 건수를 뺐다. |
| 목록 10 | 반영. 적용 안 함·대상 아님은 점선 원과 "–"로 그린다. 아직 안 한 단계(빈 원)와 다르다. |
| 목록 11 | 유지. 배지는 처리 결과를 더 잘게 보여 주는 것이 운영에 쓸모가 있다(해지 접수·환불 접수, 안내 완료의 종류). 칩은 큰 분류로 거른다. 같은 색으로 묶여 분류는 색으로 보인다. |
| 목록 12 | 반영. 칩을 처리 결과 묶음과 따로 두고 이름을 "요청이 바뀐 상담"으로 리포트와 맞췄다. |
| 목록 13 | 반영. 부제에서 건수를 뺐다. |
| 목록 14 | 반영. 부제는 고른 기간 그대로(마지막 통화 날짜에서 7일)다. |

| 대화 2 | 반영. 고객 발화의 전화번호 가운데와 인증번호를 가린다(`calls.mask_text`). |

## 2차 확인(2026-10-15)

처리 뒤 새 스크린샷으로 다른 에이전트가 다시 확인했다(구현은 보지 않음). 1차에서 "반영"이라 적은 높음·중간 지적만 확인했다. 아래는 고쳐지지 않았거나 일부만 고쳐진 것, 새로 찾은 것과 그 처리다. 나머지는 고쳐진 것으로 확인됐다.

| 확인 결과 | 처리 |
|---|---|
| [높음] 목록 1 일부 — 카드에 상담 시간과 일시가 없어 같은 고객의 두 통화를 구분할 수 없다 | 반영. 카드 모양에서는 넓은 화면에서 숨기던 칸도 모두 보인다. |
| [중간] 목록 3 일부 — 요약에 환불 불가와 그 근거가 없다(처리 내역은 "대상 아님"뿐) | 반영. 견적 없이 해지만 접수한 통화는 "환불은 접수하지 않았습니다(해지 근거 제7조 월 구독의 해지)"로 적고, 처리 내역도 "대상 아님"이 아니라 "접수 안 함"이다. 견적이 대상 아님이면 견적의 근거 조항을 적는다. 대상 여부를 확인하지 않은 통화에 "대상 아님"이라고 쓰던 것도 바로잡았다. |
| [중간] 대화 3 일부 — 요약 카드에서 날짜가 중간에서 끊긴다 | 반영. 날짜·시각·재생 위치는 줄을 나누지 않는다. |
| [낮음] 새 문제 — 상세가 열리면 좁은 화면이 제목·필터 없이 상세로 시작한다 | 유지. 상세를 목록 앞에 두라는 1차 지적(목록 2)을 따른 결과다. 닫으면 목록의 제목과 필터가 맨 위에 보인다. |
