## 지적(원문)

1. [높음] [390] 업무 API 동작 표 — 390px에서 "동작"과 "설명" 두 열만 보이고 "실행 조건"과 "사용" 열은 잘린다. 가로 스크롤 표시도 없어 어떤 동작이 고객 동의 후 실행인지 모바일에서 볼 수 없다. — 좁은 폭에서는 행마다 "설명 + 실행 조건 배지"를 쌓는 목록으로 바꾸고 영문 식별자는 숨기거나 작게 둔다.
2. [중간] [390] 상단 가로 메뉴 — "지식·정"에서 잘리고 지금 보는 "연동"이 화면 밖에 있다. — 현재 메뉴가 보이게 하거나 더 있다는 표시를 둔다.
3. [중간] [5] "주소: http://127.0.0.1:8081" — 루프백 주소는 운영팀에게 의미가 없고 개발 환경 값이 노출된 것으로 읽힌다. — 행을 빼고 연결 상태만 남긴다.
4. [중간] [5] "AI 목소리: Kore · 한국어" — 공급사 목소리 이름이라 어떤 목소리인지 알 수 없다. — 특성 정보가 없으면 지어내지 말고 "한국어"만 남긴다.
5. [중간] [2] "허용한 동작: 11개 · 그중 접수·연결 4개는 조건을 확인한 뒤 실행" — 아래 표를 다시 요약한 중복이고 내용도 어긋난다(본인 확인 후 조건이 붙은 동작이 6개, 환불 계좌 등록은 접수도 연결도 아님, 표는 "고객 동의 후 실행"이라고 씀). — 행을 빼거나 표의 조건 이름 그대로 센다.
6. [중간] [1][2] "사용(최근 7일)" 열 — 해지 접수 50회 등이 운영 리포트의 숫자와 같고, 연동 설정 화면에서 이 횟수로 내릴 결정이 없다. — 열을 뺀다.
7. [중간] [1] "음성 상담: 받음"과 "전화번호: 정하지 않음" — 번호가 없는데 "받음"이라 실제로 받을 수 있는 상태인지 알 수 없다. — "받을 수 없음(전화번호 없음)"처럼 실제 상태로 보인다.
8. [중간] [3][4] 상태 배지 — "설정됨" 배지가 업무 API 카드에만 있다. — 세 카드에 같은 기준의 배지를 두거나 모두 뺀다.
9. [중간] [4] "연결 조건" — 조항 원문을 "~한다." 문체 그대로 옮겨 길고, 다른 카드의 이름–값 형식과 다르며, 같은 줄의 다른 카드 아래에 빈 공간이 생긴다. — 짧은 항목으로 줄이고 원문은 지식·정책의 조항으로 연결한다.
10. [중간] [4] "데이터 보관: 정하지 않음" — 상담사 연결과 관계없는 카드 맨 아래에 있다. — 따로 둔다.
11. [중간] [3] 제목 옆 설명 문구 — 제목 6개 모두에 회색 설명이 붙어 있고 일부는 제목을 되풀이한다. — 정보를 더하는 "회원·결제·해지 시스템"만 남긴다.
12. [낮음] [4] 용어 혼용 — "업무 시스템"과 "업무 API", "통화"와 "음성", "AI 상담원", "AI", "자동 응대". — 하나로 맞춘다.
13. [낮음] [3][4] 실행 조건 배지 색 — "연결 조건에 해당할 때"가 "고객 동의 후 실행"과 같은 색이고, 파란 "본인 확인 후" 배지가 6행 반복된다. — 예외인 "고객 동의 후 실행"에만 색을 쓴다.
14. [낮음] [1] 표 첫 열의 영문 식별자 — 운영팀이 읽는 한국어 설명이 둘째 열에 있다. — 설명을 첫 열로 올리고 식별자는 보조 글자로 낮춘다.
15. [낮음] [1] 첫 인사 "없음 · 고객이 먼저 말합니다" — "정하지 않음"과 표기가 달라 의도인지 미설정인지 알기 어렵다. — 미설정이면 "정하지 않음"으로 맞춘다.
16. [낮음] [4][390] 업무 API 동작 카드 여백 — 제목만 다른 카드보다 안쪽에 있어 카드가 겹친 것처럼 보인다. — 같은 여백으로 맞춘다.

전체 평가(원문 요약): 세 카드와 동작 표의 구성, 메뉴·제목·여백은 다른 화면과 맞고, 장식 아이콘을 빼고 미설정 값을 "정하지 않음"으로 둔 것은 기준에 맞다. 개발 주소와 목소리 식별자 같은 내부 값, 표·리포트와 겹치고 어긋나는 요약·사용 횟수가 남아 있다. 390에서 실행 조건 열이 안 보이는 것부터 고친다.

## 처리

| 지적 | 처리 |
|---|---|
| 1 | 반영. 동작 표를 좁은 화면에서 카드 모양으로 쌓는다. 실행 조건이 첫 화면에 보인다. |
| 2 | 반영. 좁은 화면 메뉴를 줄바꿈으로 모두 보인다. |
| 3 | 유지. 주소는 실제로 설정된 연결 대상(로컬 시연의 모의 업무 시스템)이다. 지어낸 운영 주소를 넣지 않는다. 연결 상태 확인은 이번 범위에 넣지 않았다. |
| 4 | 유지. "Kore"는 음성 설정(`config/voice.toml`)에 실제로 적힌 목소리 이름이다. 목소리 특성 설명은 확인한 자료가 없어 지어내지 않는다. |
| 5 | 반영. "허용한 동작" 요약 줄을 뺐다. |
| 6 | 반영. 사용 횟수 열을 뺐다(운영 리포트와 겹침). |
| 7 | 반영. "음성 응대: 켜짐 · 전화 회선은 아직 없음"으로 실제 상태를 적었다. |
| 8 | 반영. 상태 배지를 모두 뺐다. |
| 9 | 반영. 조항의 하위 목록을 조건 하나씩으로 나눠 적고, 원문은 지식·정책의 그 조항 링크로 둔다. |
| 10 | 반영. "데이터 보관"을 따로 카드로 뺐다. |
| 11 | 반영. "회원·결제·해지 시스템"만 남기고 설명을 뺐다. |
| 12 | 반영. "업무 시스템", "통화", "AI"로 맞췄다. 약관 원문의 "자동 응대"는 원문 인용이라 그대로 둔다. |
| 13 | 반영. "고객 동의 후 실행"에만 색을 쓰고 나머지는 일반 글자다. |
| 14 | 반영. 한국어 설명을 첫 칸에, 동작 이름은 그 아래 작은 고정폭 글자로 내렸다. |
| 15 | 반영. "정하지 않음 · 지금은 고객이 먼저 말합니다". |
| 16 | 반영. 표 카드 여백을 다른 카드와 같은 컴포넌트 값으로 맞췄다. |
