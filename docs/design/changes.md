# 화면 변경 기록

## 2026-10-19 · 실시간 통화와 통화 리플레이의 움직임

**실시간 통화(`/app/live`)**

- 갱신 간격을 1초에서 250ms로 줄였다. 영역 전체를 바꾸지 않고 바뀐 부분만 맞춘다. 대화 줄은 이름으로 이어 붙여 이미 있는 줄은 그대로 두고, 새 줄은 200ms 동안 올라오며 나타난다.
- 대화를 따로 스크롤되는 영역으로 두었다. 맨 아래를 보고 있으면 새 줄을 부드럽게 따라 내리고, 위로 올려 보고 있으면 따라가지 않는다.
- 말하는 중인 AI 답은 기록된 재생 시작·끝 시각에 맞춰 글자를 차례로 드러낸다. 끼어들기로 끊긴 답은 끊긴 지점까지만 보인다.
  - 들린 글자 수는 같은 통화에서 끝까지 재생된 답의 속도로 어림한다. 기록이나 화면 수치는 바꾸지 않는다.
- 진행 단계, 상태 배지, 안내 근거는 상태가 바뀔 때 색이 부드럽게 바뀐다.
  - 지금 나가는 답의 근거는 강조한다.
  - "요청 변경" 구분선은 처음 나타날 때 한 번만 강조한다.
  - 말하는 중인 줄과 응대 중 배지의 점은 숨 쉬듯 깜빡인다.

**통화 리플레이(`/admin/replay`)**

- 이전·다음 판단, 재생 띠의 판단 표시, 재생 목록의 판단을 누르면 문서를 새로 열지 않고 영역만 바꾼다. 주소와 뒤로 가기는 그대로 동작한다.
- 조항 순위 행은 같은 조항이면 그대로 두고 새 순위 자리로 미끄러지듯 옮긴다. 확률 막대와 직전 확률 막대는 이전 길이에서 새 길이로 바뀐다.
- 재생 위치 선은 다음 판단 위치로 미끄러진다.
- 판단 표시, 재생 목록, 순위 표의 지금 판단 강조는 색이 부드럽게 바뀐다.

**공통과 하네스**

- 움직임 시간과 곡선은 `tokens.css`의 토큰으로 두었고, 움직임 줄이기 설정이면 끈다([컴포넌트 문서](components.md#움직임2026-10-19)).
- 디자인 린트가 `@media` 안에서 다시 정의한 `:root` 토큰을 앞 블록과 합치게 고쳤다. 전에는 덮어써서 모든 토큰이 정의되지 않은 것으로 보였다.
- `scripts/ui_check.py`의 대기 조건을 바꿨다.
  - 실시간 통화는 계속 갱신해 네트워크가 쉬지 않으므로 문서 로드까지만 기다린다.
  - 리플레이의 키보드 검사는 영역만 바뀌는 이동이라 주소가 바뀌기를 기다리고, 포커스를 잃지 않는지도 본다.

## 2026-10-18 · 검색 최종 평가 표시와 val 실행 분리

- 검색 고정 비교 표의 기본 분할을 test로 바꾸고, 최종 평가 분할이며 설정 고정 커밋 `89eca24`에서 한 번 실행했다는 출처를 표시한다. 판정·해석 문구는 추가하지 않는다.
- 화면 실행은 별도 `val 실행 결과` 영역에서 같은 구성의 val 기준 행과 비교한다. 완료된 val 실행이 없으면 빈 상태만 표시한다. 비용 산정은 기존 val 측정치를 유지한다.
- HTTP·작업 제출·실제 처리에서 test·check를 거부하는 회귀 검사를 둔다. 실제 처리는 원문이나 외부 클라이언트를 만들기 전에 분할을 검사한다.
- `scripts/ui_check.py`로 `admin-models`, `admin-retrieval-confirm`, `admin-models-simulated-val`을 두 폭에서 촬영한다. 마지막 화면은 임시 폴더의 가상 실행 자료이며 실제 성능 측정치가 아니다. 촬영·접근성·키보드 결과는 [스크린샷 기록](screens/changes.md)에 남긴다.
- 고정 결과는 구성별 JSON에서 읽으므로 아직 없는 `claim-check.json`과 후속 갱신될 `report.json`은 화면 표시의 선행 조건이 아니다.
