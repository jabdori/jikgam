# v2 R5 확정 측정 기준

> 처음 읽는다면: [전체 흐름 안내](overview.md) · [용어집](glossary.md)

- 상태: 실행 전 고정(2026-10-19). 결과를 본 뒤 이 문서를 바꾸지 않는다. 설정 고정은 ADR 0030, 결과는 ADR 0031에 적는다.
- 관련: ADR 0027(계산 정의·사람 확인·실행 절차), ADR 0028, ADR 0029, [v2-law-final.md](v2-law-final.md), `docs/evaluation-v2.md` §4.4·§8.4, `docs/evaluation.md` §3.2·§4.1

## 1. 무엇을 확인하나

- R5는 v2 법령 검색 후속 실험에서 가장 좋았던 구성 (m3)를 엔진에 넣은 법령 프로필이다(`config/v2/law.toml` `[r5]`, ADR 0029, `docs/v2-law-final.md`).
  - R4 검색 순위에서 조직의 적용 업종 구간만 남긴다.
  - 직전 판단의 상담 주제(확률 0.5 이상)가 있으면 그 주제 구간만 남긴다.
  - 상위 8개 중 2자리는 거르지 않은 순위로 채운다.
- R5는 같은 개발용 로그를 여러 번 쓴 탐색으로 골랐다. 개발 로그에 맞춰진 몫이 있을 수 있어서, 효과 주장은 새 미공개 시나리오에서 이 기준으로 잰 결과로만 한다.
- 비교 대상은 R0(조 단위 키워드 검색)다. 두 구성은 같은 엔진 위에서 돌고, 실행 계약은 법령 프로필만 다르다(ADR 0027과 같다).

## 2. 시나리오와 실행

- **시나리오:** 새 v2 미공개 묶음(v2b) 24개(`data/scenarios/HOLDOUT_V2B.md`).
  - 엔진 코드, 실패 분석, 메타데이터, 개발용 로그를 보지 않은 보관 에이전트가 쓴다.
  - 별도 도출자가 기대값을 가린 묶음으로 기대값을 다시 도출하고, 별도 대조자가 맞대어 판정한다.
  - 코디네이터와 엔진 쪽은 내용을 보지 않고 수와 해시만 받는다. 해시는 설정 고정(ADR 0030)에 넣는다.
  - 기존 v2 미공개 시나리오 12개는 실패 원인을 이미 들여다봤으므로 쓰지 않는다(ADR 0029).
- **반복과 순서:** 시나리오별 3회. R0 3회를 먼저, R5 3회를 이어서 돌린다. 지연 측정이 서로 간섭하지 않게 동시에 돌리지 않는다.
- **실행 계약:** ADR 0027과 같다. 다만 다음이 다르다.
  - 시나리오 파일: `data/scenarios/org_a_v2b_holdout.jsonl`
  - 고객(실행기): `domain/org_a/customers_v2b_holdout.json`
  - 모의 업무 API 데이터: `customers.json`, `customers_holdout.json`, `customers_v2_holdout.json`, `customers_v2b_holdout.json`을 이 순서로 합친다(기대값을 낸 구성과 같다).
  - 법령 프로필: r0, r5
- **설정 고정:** 엔진·판별·생성·시뮬레이터·판정기·보고기 코드, 설정, 시나리오와 고객 파일, 법령 자료(구간, 구간 정보, R5 구간 메타데이터, 주제 질문), 임베딩 캐시, 모의 업무 API 소스와 실행 계약을 ADR 0030의 고정 목록에 넣는다. 실행은 고정 커밋의 수정 없는 작업 사본에서 한다.

## 3. 주 지표: 법령 근거 포함률

- **정의:** 유효 실행 × 정답 법령 항목 단위로 센다.
  - 정답 법령 항목은 고정한 시나리오 파일의 `expected.law_evidence` 항목이다.
  - 상담 근거는 그 세션에서 노출한 제안들의 인용 근거 합집합에 든 법령 구간이다. `docs/evaluation.md` §4.1 항목 10이 보는 근거 집합과 같다(`jikgam.sim.judge`).
  - 항목이 근거에 들어갔다는 것은 그 구간들이 항목의 대표 위치나 대체 위치 하나를 공백을 뺀 글자의 절반 이상 덮는다는 뜻이다. `docs/evaluation-v2.md` §4.2와 항목 10의 법령 판정과 같은 기준이다.
  - 포함률 = 들어간 항목 수의 합 / 정답 항목 수의 합(구성마다 유효 실행 전체).
- **판정:** R5 − R0이 +10%p 이상이고, 95% 구간의 아래 끝이 0보다 크면 "R5가 근거 단계에서 낫다"로 본다. 둘 중 하나라도 아니면 "근거 단계에서 낫다고 할 수 없다"로 적는다.
- 이 지표는 로그와 고정 기대값에서 코드로 계산한다. AI 판정이 들어가지 않으므로 사람 확인 일치율로 보류하지 않는다.
- 세션 합집합으로 정한 이유: 항목 10이 세션 합집합으로 판정한다. ADR 0029는 세션 단위 지표를 판정에 쓸지 다음 기준에서 먼저 정하기로 했다.

## 4. 보조 지표

| 지표 | 정의 | 조건 |
|---|---|---|
| 통과율 | `docs/evaluation.md` §4.1. 항목 10은 조직 A 조항 id와 법령·고시 정답 근거를 모두 덮어야 한다(`docs/evaluation-v2.md` §4.4) | R5 − R0 점추정 −5%p 이상이면 "나빠지지 않았다" |
| 근거 없는 주장 비율 | ADR 0027 정의(노출 제안마다 생성 입력 전체로 판정, 고정 문구 제외, 유효 실행의 주장 합을 분모로) | 점추정 R5 ≤ R0 |
| 근거 갱신 | `docs/evaluation.md` §3.2, `jikgam.sim.metrics`. 미갱신은 무한대로 넣는다 | R5 p95 ≤ 500ms |

- 통과율과 근거 없는 주장 비율의 차이는 95% 구간을 함께 보고한다. 이번 기준에서 통과율의 "나아졌다" 판정은 하지 않는다.

## 5. 계산 정의(ADR 0027을 따른다)

- **유효 실행:** 고객 AI 지시 준수가 '준수'로 판정된 실행만 집계한다. 무효와 준수 미판정은 따로 센다. 준수 미판정이 남으면 주 지표와 보조 지표 모두 판정 보류다.
- **판정 실패:** AI 판정기와 주장 판정기의 응답에 필수 항목이 빠지거나 형식이 틀리면 2·4·8초 뒤 최대 3번 다시 부른다(`docs/evaluation-v2.md` §4.5). 그래도 남은 판정 불가는 ADR 0027대로 해당 조건을 판정 보류로 둔다.
- **구간:** 시나리오 단위 짝지은 부트스트랩이다(10,000회, seed 20261016).
  - 고정 시나리오 파일의 시나리오 24개에서 같은 수를 복원 추출한다. 뽑힌 시나리오의 두 구성 유효 반복을 모두 쓴다.
  - 비율이 정해지지 않는 추출(유효 실행이나 항목이 없음)은 그 지표에서 빼고, 쓴 추출 수를 보고한다.
  - 주 지표와 보조 지표는 같은 추출을 쓴다. 구간은 2.5·97.5 백분위다.
- **사람 확인:** 실행 뒤 사용자가 모델 판정과 구성(R0/R5, 구간 id의 구성 단서)을 가린 한 화면에서 확인한다.
  - 노출 제안의 주장 30개(근거 있음/없음): 일치율 0.80 미만이면 근거 없는 주장 비율 조건이 판정 보류다.
  - AI가 판정한 시나리오 항목 10개(통과/실패): 일치율 0.80 미만이면 통과율 조건이 판정 보류다.
  - 표본은 ADR 0027의 도구(`jikgam.v2.e2e_check`, seed 20261016)로 뽑는다.
- **독립 재계산:** 측정과 분리된 검토자가 비공개 원본 로그, 주장 판정 기록, 고정 기대값에서 이 문서의 수치를 보고기 코드를 쓰지 않고 다시 계산해 대조한다. 어긋나면 원인을 찾아 기록하고, 판정은 이 문서의 정의대로 한다.

## 6. 비용 상한과 중단

- 이 확정 측정 작업 전체의 유료 호출(고객 AI, 판별, 생성, 시나리오 판정, 주장 판정, 도구 점검 실행)은 **$45**까지다. 에이전트 작업(시나리오 작성, 재도출, 대조, 독립 재계산)은 넣지 않는다.
- 누적 비용이 상한에 닿으면 그 자리에서 멈추고 보고한다. 주장 판정 전에 남은 예산으로 끝낼 수 없다고 추정되면 시작하지 않고 보고한다.
- 멈춘 측정은 판정하지 않는다(판정 보류). 이어서 할지는 사용자가 정한다.
- 실행이 다른 이유로 멈추면 멈춘 곳과 이유를 기록하고, 같은 계약으로 남은 회차만 다시 돈다(ADR 0027 절차 7).

## 7. 보고

- 판정표(주 지표, 보조 지표 셋, 각 값·구간·조건·결과), 비용(구성별, 항목별), 사람 확인 일치율.
- 보고만 하는 것: 무효 실행 수, 항목 1~10 실패 수, 무효 제안 노출, 근거 정밀도, 법령 정밀도, 세션당 법령 근거 토큰, 근거 갱신 p50.
- 실패한 실행의 단계별 분류(`docs/v2-e2e-failures.md`의 등급과 같은 방식). 판정에 쓰지 않는다. 시나리오 원문과 기대값은 보관 에이전트만 읽고, 문서에는 수와 구간 id만 둔다.
  - R5의 등급 2(후보에 있었지만 상위 8개 밖)는 메타데이터 거르기로 빠진 경우와, 남았지만 8위 밖인 경우로 나눠 적는다. 전체 순위는 거르기 전 R4 검색 순위다.
- 결과가 기대와 달라도 판정까지 마치고 ADR 0031에 그대로 적는다.

## 8. 한계

- AI 고객과 AI 판정기로 잰 합성 결과다. 운영 성과가 아니다.
- 시나리오 24개 × 3회다. 통과율 차이의 구간은 넓을 수 있다(ADR 0028에서 12개로 폭 36.4%p).
- R5의 주제 판단은 엔진의 첫 판별 요청에 더한 질문이라 직전 판단의 주제를 쓴다(한 턴 늦음). 세션의 첫 검색은 업종으로만 거른다.
